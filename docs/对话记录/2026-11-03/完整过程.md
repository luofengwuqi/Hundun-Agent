### 🍜 馄饨/助手 · 16:24:49

核实结果如下（以下三条都会影响设计）：

**OpenClaw 的实际记忆机制**：它采用两层，`memory/YYYY-MM-DD.md`（每日日志，只追加，会话开始时读今天和昨天）和 `MEMORY.md`（精选长期记忆，只在私密主会话加载）。写入规则是「决策/偏好/持久事实 → MEMORY.md；日常笔记 → 日文件；用户说『记住这个』就立刻落盘」。它还有一个很巧的机制：**会话快满、即将压缩上下文之前，会静默跑一个回合，逼迫模型先把记忆写下来**，然后回复 `NO_REPLY`，用户无感。权限阶梯是 `AGENTS.md`（人类锁定）> `SOUL.md`（AI 可改）> `MEMORY.md`（完全开放）。它的一句原话很值得抄：「上下文 = 缓存，文件 = 真正的记忆」。

**WorkBuddy 专家包的真实结构**：`.codebuddy-plugin/plugin.json` + `agents/<agentName>.md`（人格与流程的全文本）+ `avatars/` + 可选的 `skills/`。你的 `my-experts/plugins/` 目前是空的，所以这是第一个。**关键差异**：专家包本身**没有记忆、没有心跳、没有定时器**，它只是一段每次重新加载的人格文本。所以 OpenClaw 的三层能力必须拆开映射：

| OpenClaw | 这里落到哪 |
|---|---|
| `AGENTS.md`（操作规程，人类锁定） | 专家包 `agents/xxx.md` 的正文 |
| `SOUL.md` / `USER.md` / `IDENTITY.md` | `~/life/` 下同名文件，**可随相处不断改写** |
| `MEMORY.md` + `memory/YYYY-MM-DD.md` | 同构，放 `~/life/` |
| `BOOTSTRAP.md`（一次性引导访谈） | 保留，访谈完删除 |
| `TOOLS.md` / `BOOT.md` / `skills/`（工具技能） | **砍掉** ← 这就是你说的「去掉过强的工具性」 |
| `HEARTBEAT.md`（30 分钟心跳） | **改造**成 `CHECKPOINTS.md`，由 WorkBuddy 定时任务读取 |
| cron / heartbeat 调度器 | WorkBuddy 定时任务（每天定点唤醒一个会话） |

这里有两点必须提前说清，否则会错位：**WorkBuddy 没有心跳机制**，只有 cron 式的定时任务，所以 OpenClaw 那种「每 30 分钟醒一次看看」在这里不成立，而这恰好符合你要的方向：我们要每天 2–3 个定点，而不是高频轮询。另外 **WorkBuddy 也没有「压缩前静默写记忆」的钩子**，替代方案是把写记忆的责任写进人格正文（每次对话结束前必须落盘），再让晚间定时任务补一次漏。

## 1. 四个里程碑

每个里程碑结束都能**真的用**，不是半成品。顺序按「不修就白做」排，不按功能清单排。

```
M0 止血    把「写着有、实际没有」的地方改成真的         ← 不改功能
M1 记得    对话原话落盘 + 约定有载体                    ← 本命
M2 说话    打扰整套重建（调度、送达、时效、缺席）        ← 最大的一块
M3 收口    备份、人格、联网、视觉                        ← 可以慢
```

**为什么 M1 在 M2 前面**：D002 是「像人一样记得」，打扰只是它的一个出口。**记不住的软件，说话再准也只是个闹钟。**

### P-08 `COMMITMENTS.md` 的读写（GAP-07）

> **状态：已做（2026-11-04）。** `life.js` 里五个函数：`listCommitments`／`readCommitment`／`addCommitment`／`updateCommitment`／`removeCommitment`（第五个是规格里没写但状态机需要的——「待延后」遇到时效已过是**删行**，不是「已结案」，不给删行就实现不了）。`test.mjs` 新增 17 项，70 通过 / 0 失败。

- 载体已建（`life.js` 的 `TPL_COMMITMENTS`：四列表格）。补四个函数：`listCommitments()`／`addCommitment()`／`updateCommitment()`／`readCommitment()`。
- **四列：`什么事`／`到期日`／`结局`／`消息`。后两列问的不是同一件事，不能合并（D061）**：
  - `结局` = **这件事怎么样了**，他答了才有。取值：`—`（还没答）／`成了`／`没成`／`没去`。
  - `消息` = **这句话送到哪一步了**，机器判定，不用人填。取值：`未问`／`已送达`／`待延后`／`已结案` —— **不要用布尔值**，这四态是 M2 整个状态机的地基（P-12）。
- 状态机（只走 `消息` 列）：`未问 → 已送达 → 已结案`；`未问 → 待延后 →（已送达 | 删行）`。**不回退、不跳级。** `结局` 一旦写下不再改。
- 可选列 `pinned`（D053：他说过「到那天一定要问我」）。**解析必须按表头名定位列，不能按下标**——`pinned` 是可选列，出现时整行变 5 列，按下标会读到错位的值。
- **旧文件兼容（种子机制不会改写已存在的文件）**：三列的老 `COMMITMENTS.md` 不会因为模板换了就自动变四列。读取时缺 `消息` 列按 `未问` 处理，**下一次写入时补上表头与该列的值**（一次迁移，不加版本号）。否则老文件里的约定会被判成「读不出状态」——又是一次静默失效。
- 通过标准：手动往文件里加一行，程序读得到；程序改状态，文件里那一行真的变了（不是只改内存）；**加一列 `pinned` 后其余四列仍读得对**。

### P-09 静默提取约定（D049／F06-1，**最容易做歪的一条**）

> **状态：已做（2026-11-05）——链路已通，模型的判断力未验。**
> `blocks.js` 加第四种块 `<commit>`，单独一个桶（和 memory 混在一起就永远没人问起）；`life.ingestCommits()` 做三件事：判据、相对日期锚点、同一件事改而不加。系统提示词里写死了判据、「宁可漏不要多记」、「不要问要不要记着」。测试 14 项（`[1e]`）。
> **没验的那一半必须说清楚**：`F06-01`／`F06-02` 的实质是「模型会不会滥用这个通道」，那只能用真模型跑。本机 Electron 起不来（`llm.js` 走 `electron.net`），所以只验了「给了 commit 块就能正确落盘、缺日期会丢、相对日期带锚点、重复会改」，**没验「它会不会把每句话都记成约定」**。这条要等真机：跑一整天，看 `COMMITMENTS.md` 里有没有不配留下的行。

- 通道已有：`blocks.js` 解析 `<memory>` 三块 → 加第四种 `<commit>`。
- 系统指令里写死判据：**有具体时间指向 且 有具体事**，缺一个不记（F06-1）。
- 日期不确定时不换算绝对日期，存相对表达 + 当天锚点（§1.6 第六条）。
- **不插确认、不显示「已记录」**（D049，他明确否掉了当场问）。
- **最大的风险：模型会滥用这个通道，把每句话都记成约定。** 防线是判据写死 + 验收 F06-01／F06-02（「我最近想多写点代码」不得被记）。
- 通过标准：`F06-01`、`F06-02`。

> **实现细节（写给二期／M2 的人，免得重新推一遍）**：
> - `<commit>` 行格式 `什么事 | 到期日`，**竖线分格**，不是逗号——事由他自己说，里面天然带标点。
> - 到期日能确定就 `YYYY-MM-DD`；拿不准存 `下周三@2026-11-05`（相对表达 + 当天锚点），**换算留给 M2 的调度器**，这里不猜（§1.6 第六条）。
> - 同一件「什么事」还没结案时再出现，是**改**不是加（`updateCommitment`）；**已结案的不碰**——那件事说完了，他再提是另一件事。
> - 一次最多处理 5 行：模型偶尔会把整段对话复述成约定，截断比全信安全。

### P-11 打扰参数落库（D045，现存 bug）

> **状态：已做（2026-11-05）。** `config.json` 增 `disturb: { on, windows, dailyLimit }`；`store.read()` 对这块单独做浅合并（顶层展开只换整块，老配置里只有 `{on:true}` 时另外两个会一起消失，而读它的人不会想到兜底）。界面四个动作全走 `cfg:set`：总开关、时段增删、每日上限步进。测试 9 项（`[3b]`）。
> **一个顺手修掉的**：`App.vue` 的 `sanitizeLive` 只过滤三种记忆块，**`<commit>` 会漏到界面上**——流式时用户能看见那个标签。加第四种块时必须同时改这里，否则「静默提取」在最显眼的地方不静默。
> **一个改掉的做法**：时间输入没用 `<input type="time">`，它的显示格式跟着系统 locale 走，英文环境下会变成「01:00 PM」，中文界面里混 AM/PM 比多写几行解析更糟。改成手写文本输入，接受 `9:30`／`930`／`09:30`，失焦规范化，输错退回原值。

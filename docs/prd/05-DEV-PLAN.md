## 1. 四个里程碑

每个里程碑结束都能**真的用**，不是半成品。顺序按「不修就白做」排，不按功能清单排。

```
M0 止血    把「写着有、实际没有」的地方改成真的         ← 不改功能
M1 记得    对话原话落盘 + 约定有载体                    ← 本命
M2 说话    打扰整套重建（调度、送达、时效、缺席）        ← 最大的一块
M3 收口    备份、人格、联网、视觉                        ← 可以慢
```

**为什么 M1 在 M2 前面**：D002 是「像人一样记得」，打扰只是它的一个出口。**记不住的软件，说话再准也只是个闹钟。**

### P-07 对话原话落盘（D028／GAP-03）

- `life.js` 加 `appendChat(role, text)` → `⟨身份⟩/chat/YYYY-MM-DD.md`，行格式：`HH:MM [你|我] 正文`。
- `life.js` 的目录初始化加 `chat/`；`search.js` 的索引范围加 `chat/`（D023 的检索语料由此变厚）。

### P-08 `COMMITMENTS.md` 的读写（GAP-07）

> **状态：已做（2026-11-04）。** `life.js` 里五个函数：`listCommitments`／`readCommitment`／`addCommitment`／`updateCommitment`／`removeCommitment`（第五个是规格里没写但状态机需要的——「待延后」遇到时效已过是**删行**，不是「已结案」，不给删行就实现不了）。`test.mjs` 新增 17 项，70 通过 / 0 失败。

- 载体已建（`life.js` 的 `TPL_COMMITMENTS`：四列表格）。补四个函数：`listCommitments()`／`addCommitment()`／`updateCommitment()`／`readCommitment()`。
- **四列：`什么事`／`到期日`／`结局`／`消息`。后两列问的不是同一件事，不能合并（D061）**：
  - `结局` = **这件事怎么样了**，他答了才有。取值：`—`（还没答）／`成了`／`没成`／`没去`。
  - `消息` = **这句话送到哪一步了**，机器判定，不用人填。取值：`未问`／`已送达`／`待延后`／`已结案` —— **不要用布尔值**，这四态是 M2 整个状态机的地基（P-12）。
- 状态机（只走 `消息` 列）：`未问 → 已送达 → 已结案`；`未问 → 待延后 →（已送达 | 删行）`。**不回退、不跳级。** `结局` 一旦写下不再改。
- 可选列 `pinned`（D053：他说过「到那天一定要问我」）。**解析必须按表头名定位列，不能按下标**——`pinned` 是可选列，出现时整行变 5 列，按下标会读到错位的值。
- **旧文件兼容（种子机制不会改写已存在的文件）**：三列的老 `COMMITMENTS.md` 不会因为模板换了就自动变四列。读取时缺 `消息` 列按 `未问` 处理，**下一次写入时补上表头与该列的值**（一次迁移，不加版本号）。否则老文件里的约定会被判成「读不出状态」——又是一次静默失效。
- 通过标准：手动往文件里加一行，程序读得到；程序改状态，文件里那一行真的变了（不是只改内存）；**加一列 `pinned` 后其余四列仍读得对**。

### P-09 静默提取约定（D049／F06-1，**最容易做歪的一条**）

> **状态：已做（2026-11-05）——链路已通，模型的判断力未验。**
> `blocks.js` 加第四种块 `<commit>`，单独一个桶（和 memory 混在一起就永远没人问起）；`life.ingestCommits()` 做三件事：判据、相对日期锚点、同一件事改而不加。系统提示词里写死了判据、「宁可漏不要多记」、「不要问要不要记着」。测试 14 项（`[1e]`）。
> **没验的那一半必须说清楚**：`F06-01`／`F06-02` 的实质是「模型会不会滥用这个通道」，那只能用真模型跑。**本机 Electron 能跑**（2026-11-05 更正：此前记的「起不来」是被环境注入的 `ELECTRON_RUN_AS_NODE=1` 骗了，清掉即可），所以这条可以自己验了，只是要连续跑一整天才有意义。**要验的是「它会不会把每句话都记成约定」**——跑一整天，看 `COMMITMENTS.md` 里有没有不配留下的行。

- 通道已有：`blocks.js` 解析 `<memory>` 三块 → 加第四种 `<commit>`。
- 系统指令里写死判据：**有具体时间指向 且 有具体事**，缺一个不记（F06-1）。
- 日期不确定时不换算绝对日期，存相对表达 + 当天锚点（§1.6 第六条）。
- **不插确认、不显示「已记录」**（D049，他明确否掉了当场问）。
- **最大的风险：模型会滥用这个通道，把每句话都记成约定。** 防线是判据写死 + 验收 F06-01／F06-02（「我最近想多写点代码」不得被记）。
- 通过标准：`F06-01`、`F06-02`。

> **实现细节（写给二期／M2 的人，免得重新推一遍）**：
> - `<commit>` 行格式 `什么事 | 到期日`，**竖线分格**，不是逗号——事由他自己说，里面天然带标点。
> - 到期日能确定就 `YYYY-MM-DD`；拿不准存 `下周三@2026-11-05`（相对表达 + 当天锚点），**换算留给 M2 的调度器**，这里不猜（§1.6 第六条）。
> - 同一件「什么事」还没结案时再出现，是**改**不是加（`updateCommitment`）；**已结案的不碰**——那件事说完了，他再提是另一件事。
> - 一次最多处理 5 行：模型偶尔会把整段对话复述成约定，截断比全信安全。

### P-09b 档案写成要求，写入是覆盖（D079）

> **状态：已做（2026-11-05）。** 照 openclaw 的 user-model 契约改写入协议。测试 19 项（`[3j]`，全套 344）。

- **`USER.md` 结构**：`## 关于他`（事实：称呼、做什么、作息）＋ `## 要求`（他对你怎么说话的要求）。每条两行——`<!-- observed: 日期 | status: active -->` 换行 `- [主题] 正文`。
- **为什么是要求不是观察**：「他喜欢简短」是观察，读过就淡；「回答保持简短」是要求，会被执行。偏好被读进上下文几轮后就失效，唯一稳的办法是写成能直接执行的句子。
- **覆盖不追加**：同主题（或相似度 > 0.75）就改原来那条，旧的标 `superseded` 留在原地。追加式偏好历史会让模型从旧值回答——这是实测的失效模式，不是洁癖。
- **三道写入闸**（都在 `life.js` / `conversation.js`）：
  1. 一字不差跳过（召回防回环）——判断用严格相等，不用相似度。
  2. `provenance: 'scheduler'` 的轮次不写任何记忆——那轮的话全是它自己编的。
  3. 相似度分母用并集，不用较小那条。
- **老文件**：只升「还空着」的那份（五节全「（待访谈）」）；已有内容的原样保留，硬转会把他写的话揉坏。
- 通过标准：`F06-04` 的实质是「它记不记得住他的偏好」——这要真机跑几天才看得出。**结构上已就位，行为未验。**

### P-12 送达标记（D057，**整个 M2 的地基**）

> **状态：已做（2026-11-05），与 P-10 一起落的。** 状态机只走 `消息` 列（D061），四种走法：送达 → `已送达`；没送到·时效弱 → `待延后`；没送到·时效强 → 删行；已是 `待延后` 又没送到 → 删行（延后只给一次）。`store.js` 增 `disturbLog` 计数器，**只在「未问 → 已送达」时加一次**。
> **送达判据是三段**：窗口可见 → 算送到；窗口不可见 → 弹通知且**必须收到 `show` 事件**（调过 `show()` 不算——没有通知守护进程的桌面上它什么也不做）；都没有 → 不标记已问。最后一段是这个地基的全部意义：**按发出标记，关机那晚那句就永远算问过了，延后从此不会发生，而且不报错。**
> **没验的**：`F06-26` 要真关一次进程跨过到期时刻，只能真机做。

- 状态机（**只走 `消息` 列**，D061）：`未问 → 已送达 → 已结案`；`未问 → 待延后 → (已送达 | 删除)`。
- **按「送达」标记，不按「发出」**（F06-3 第 4 步）。送达 = 应用在运行 且（窗口可见 或 通知已展示）。
- **这一条写错，延后功能整个不会发生**：按发出标记 → 关机那次的记录永远丢了。
- 已知误判方向：通知弹了但人没看见 → 判成已送达 → 结案。**错在少问一句，这是安全的那个方向。**
- 通过标准：`F06-26` —— 关进程跨过到期时刻再开，`消息` 列**不得**是 `已结案`（时效在 → `待延后`；过时 → 删行）。**注意别把「结局」写进这条判据**：`结局` 列此时应该是 `—`，它证明的是「没问过」，不是「没送到」。

### P-13 时效判断与延后（D058）

> **状态：只做了第一版，在 P-10 里。** `schedule.timeliness()` 用关键词判强／弱，**默认强**（认不出来就当过时即删）。它能过 F06-27 那个「大大后天」的例子，也能让「把 README 写了」延后一次；但它不认识反讽、否定和比喻（「谈崩了，不想谈」里有「谈」）。**换成真判断的时候必须保住两条**：默认强，以及强词优先于弱词（否则「谈项目」会被「项目」拖进 weak）。

- 判据不是「重不重要」，是**「这句话现在说还对不对味」**：有明确时点的事（谈项目、开会、交稿）时效强；持续中的事（学嵌入式、长期项目）时效弱。
- 时效强 → 过时即删，不补不攒不汇总（F06-27）。
- 时效弱 → 延后**一次**，且**措辞必须重写**，不能照搬（F06-28）。
- 硬上限：只一次／不合并／不因延后提频。
- 通过标准：`F06-27`、`F06-28`、`F06-29`、`F06-31`。

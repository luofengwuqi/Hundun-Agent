> **这一轮两句话，一句改机制，一句改范围**：
> 1. 「太长时间不在，不如像老朋友一样只道一句好久不见」→ **D059**（在 ④ 的封条上划出一道**有理由的**口子：**禁止日历周期，允许缺席事件**）

> **⚠ D059 不是给 ④ 复活开的门。** ④ 死的原因是「每天都会到，所以每天都要说一句，剩下的只能填套话」；「好久不见」以缺席为前提、一段缺席只说一次，**它不会在明天再来一次**。判据写好放在档案里：**这段话明天、后天、大后天会不会以同样形式再来？会，就是 ④。**

> **这一轮真正的收获是一个措辞上的红线**：「我一直在等你」被明确判死——**它把等待变成他的人情债**。他的价值观里最要紧的一条是「我不亏欠」，所以凡是让他觉得欠了什么的句子，一个都不能用。同类：报天数、问他去哪了、说「你终于来了」。

### D036 记忆自动备份，并外挂 git 仓库用于多设备同步
- 内容：`~/life/` 自动备份；并挂一个用户自己的 git 仓库，使多台设备共用同一份记忆。

  2. **触发时机**：自动 commit 在本地很安全；push 需要远端与凭证，**会失败**。失败必须静默降级（D021），不能让用户看见报错，也不能因为推不上去就阻塞使用

- **一个反证**：用户本轮主动问「为什么会主动提醒用户」。若这真是他要的，他不会问。**提问本身就说明他不认这个需求。**

### D043 「打扰」＝对约定的回访，不是到点开口的检查点
- 内容：**F06 的触发源被换掉了。** 旧形态是「时钟驱动」：到了设定时刻，让它开口说点什么（内容由 `CHECKPOINTS.md` 提供，而那份种子写的是「早间定计划／晚间复盘」）。新形态是**「对话驱动」**：只在一场对话里双方**立下过约定**（哪天要做什么事）之后，到那天、落在用户划定的允许时段内，它来问一句**关于那件事**的话。

- 适用版本：v0.1 起（替代 D016 的检查点部分，第二次；重新界定 D039／D040 的容器语义）
- 影响：**F06 整节重写**、`CHECKPOINTS.md`（→ O11）、F08（人格基调）、F11（托盘与通知）、Q019（销）、Q020（销）、新增 Q021–Q023、X-09、X-10、GAP-07
- **用户原话（整段，这是他第一次把这件事说完整）**：

- **这个例子为什么救得回来（形态差异是决定性的，不是措辞差异）**：

  | | 旧形态（时钟检查点） | 新形态（约定回访） |
  | --- | --- | --- |
  | 触发源 | 时钟到了 | 对话里真的有过一个约定 |
  | 它开口的内容 | 空的（要 `CHECKPOINTS.md` 教它说什么） | 具体的（用户自己说过的那件事） |

  | 出口 | 容易退化成每天定时安慰（撞 D032） | 天然落在「知道目标」或「说完了」上 |
  | 与 D033 的关系 | 「在场」只靠出现频率撑 | 「**记得**」有了可见证据——它记得你后天要谈事 |

  旧形态的死因就在第一格：**触发源是时钟，内容就必须由别处提供，而那份提供内容的东西（`CHECKPOINTS.md`）写的是通用套话**。这解释了为什么它怎么做都像例行公事。

  2. **一次只问那一件事**，不附带复盘、不附带「顺便你今天的计划呢」。
  3. **允许时段之外绝不开口**（D045）。约定到期时若不在时段内，等到下一个时段，不擅自提前或延后成「催」。

- 备注：本条同时确认了「监督」是可接受的，但带一个硬限定——原话「**并不需要过于苛刻的监督**」。苛刻与不苛刻的分界线不在频率上，在**说话的方式**上：问「谈得怎么样啦」是关心，问「你昨天说的今天要做，做了吗」是苛刻。这条界限写进 F08。

### D044 对外宽容温柔，对内理性中立客观
- 内容：**人格被拆成两层，两者不共用同一套语气。**

- 来源：G06-7 第 1 段（原话「这个软件对外(用语)是极度宽容温柔的 而对内(分析用户这个人 分析方向 分析计划)是极度理性中立客观」）
- 适用版本：v0.1 起
- 影响：**F08 整节重写**、SOUL.md 的写法定型、§1.6 新增第七条、Q022
- **这条为什么重要**：它回答了本项目最难的一处张力——D031（默认来意即疲惫，要安慰）与 D023（要拿得出方向，要指导）此前是靠「先安慰后指导」的流程拼起来的，本质是二选一排队。**拆成内外两层之后两者不再竞争：温柔是表达层，理性是判断层。** 温柔不牺牲判断力，理性不要求语气变冷。

### D056 「重要」有两个判据，但只能用来量事，不能用来量人
- 内容：**判定一件事重要，有两条路**：① 他频繁提到；② 他明确表示过这件事重要。**两条都成立，但统计的对象只能是「这件事」，不能是「他在这件事上的表现」。**
- 状态：已确认（**但其中一条与我上一轮的写死相冲突，见下，已按他的意思改，并划出不可越过的线**）

- 来源：G06-10（原话「**用户频繁提到的就是重要的 或者用户表示过某个东西重要**」）
- 适用版本：v0.1 起
- 影响：**D053（门槛改写）**、D050、X-10、F02、F04、F06、USER.md 的写法
- **⚠ 这条和我上一轮写的直接冲突，必须说明。** 我上一轮写死的是「**软件不得自己判定某条约重要**，一旦它开始评级，不评判整套就废了」。他说「频繁提到的就是重要的」——**这就是让软件自己判**。
- **我核了一遍，是我把两件事挤在一个词里了。** 「重要」在这个产品里有两个用途，它们的代价完全不同：

| | 用途 | 统计对象 | 能不能做 | 为什么 |
| --- | --- | --- | --- | --- |
| **A** | 判断「什么在他生活里有分量」——影响记什么、聊什么、怎么称呼那件事 | **事**（这个项目他提了 7 次） | **可以** | 这是关于事的观察，不构成对他的评价。而且**这恰恰是「记得」的一部分**（D033） |
| **B** | 判断「哪条约要破例补跑」——D053 的例外 | **事**（这条约定他说过重要） | **可以，但只补一次** | 破例本身是善意的，但它最容易滑成优先级排序，所以上限必须硬 |

- **不可越过的那条线（写死）**：**统计「事的分量」可以，统计「人的表现」不行。**
  - 可以：「这个项目他提了七次」「他说过这件事要紧」→ 导出动作：记进 `MEMORY.md` 的「进行中的事」、对话里认真对待、到期补问一次。
  - **不行**：「他答应过七次，做到两次」「他最近提的事越来越小」→ 这类统计**一次都不许出现**，它对应不到任何输出动作，纯属攒账（D044 判据 / X-10 红线 2）。
  - **判据一句话**：数的是**这件事**，不是**他**。前者是记得，后者是打分。
- **「频繁提到」的实现边界**（否则这条会失控）：
  1. **不算次数就下结论。** 「他好像挺在意这个」可以来自印象，**不必维护一个计数器**。真要计数，也只能在单次对话的上下文里看，不做跨月累计——跨月累计就是一份档案。
  2. **不得因「重要」提高打扰频率。** D045 的每日上限是硬的，重要与否都不改配额、不加时段。**一旦「重要」能换更多打扰，它就变成了催办。**
  3. **不得因「重要」延长追踪。** 重要的事过期了也照 D053 处理（不补），唯一例外仍要他当场开口。
- **判定结果写哪儿**：`MEMORY.md` 的「进行中的事」（事实），**不写「重要」这个结论本身**。判断可以存在，标签不许存在——「这件事对他很重要」一旦写进文件，就成了他下次必须继续重视的理由。
- 关联：**D053**、D050、X-10、D044、D033、F02、F04、F06、USER.md

- **一个必须承认的误判**：「通知弹出来了，但他在开会／在别处没看见」会被判成**已送达**，从而结案。**这个代价我认了，理由是方向安全**——误判的结果是「少问一句」，不是「多问一句」。整个产品（§1.6、D044、D054）的倾向都是宁可少说。

### D058 送不到可以延后一次，但时效过了就永远不说了（修正 D051）
- 内容：**消息没能送达时，允许延后到下一次「他」在的时候再说——但前提是那句话在那个时候说还成立。时效过了，不问，不攒，不汇总。**
- 状态：已确认
- 确认人：用户｜确认方式：原话｜确认日期：2026-11-04
- 来源：G06-11（原话「**第二种情况 我不在线 软件问失败了 允许延后问 但是关于时效性特别强的就别问了（后天有个项目 我大大后天才上线 问了意义不大）**」）
- 适用版本：v0.1 起
- 影响：**D051（被本条修正）**、D053、D029、O12、F06-5、F06-11、F06-12
- **⚠ 这是修正，不是补充，必须这么说。** D051 原话是「那段时间 没在线上 过去了就过去了」，当时的结论是「人不在就作废，不补不顺延」。**今天这句把它改掉了**：人不在，可以延后，条件是时效还在。
  - 我上一轮把它写成「一律作废」，**他当时没反对，是因为他还没想到这一层**（软件已经尝试过、只是没送到，和软件压根没尝试，是两件事）。
  - **现在这条更细，也更对**：作废一整类，等于把「我尽力了但没送到」和「我不该问」混成一件事。

- **「延后」和「补」的区别（这一条必须写死，否则「使劲补」会顺着这个词复活）**：

| | 那件事的时点 | 动作 | 归属 |
| --- | --- | --- | --- |
| **延后** | **还没过**（话现在说仍然对味） | 下次他在的时候正常送达，一次 | D058 |
| **补** | **已经过了**（话现在说变味了） | 默认不问；唯一例外见 D053 | D051／D053 |

- **判据只有一个词：时效。判法不是「重要不重要」，是「这句话现在说还对不对味」。**
  - **时效强（不延后）**：有明确时点、过了就变味的事——谈项目、开会、面试、交稿、当天的约定。**过了那个点，问「怎么样啦」就从「陪你等」变成「来收账」。**
  - **时效弱（可延后）**：持续中、三天后问依然成立的事——学嵌入式、写开源、健身、某个长期项目。**这类的「后来呢」是真的想知道。**
  - **他给的例子就是最强的一条**：后天谈项目，大大后天才上线——**「后天」这个词本身已经过期了**，那句话说出来只能是「你之前说的那个谈了吗」，这是查账。
- **三条硬上限**：
  1. **延后只给一次。** 送达后不管他回不回，立即结案，不再有第二次延后。
  2. **不累积。** 三条约定都没送到，不合成一条「你有三件事」——那是缺席审判（D051 原本要封的东西，仍然封着）。
  3. **延后不占用新一天的配额语义**，但也不额外增加上限（D045 不动）。**送不到就少说一句，不吃亏。**
- **一个必须顺着改的地方**：延后送达时，**措辞必须重写，不能原样照搬**。到期是「后天那个谈得怎么样啦」，延后两天就是「前两天那个谈完了吗」。**照搬等于让它露馅，也等于把过期的话硬塞进现在的时点。**
- **D053 的地位跟着变了**：「重要」的例外现在只在**时效已过但仍然有意义**的那一小块里起作用（比如「月底交稿」这种长期约定，到期日过了但事还没结束）。**它不再是「所有过期约定的补问许可」，而是「时效模糊地带的唯一破口」。** 上限仍然是**一次**。

### D059 长时间不在之后，第一句只说「好久不见」（新开，改 ④ 的边界）
- 内容：**他隔了很久才回来，它说的第一句话不是提醒、不是复盘、不是问候式套话，而是一句「好久不见」。只这一句，说完就停。**
- 状态：已确认
- 确认人：用户｜确认方式：原话｜确认日期：2026-11-04
- 来源：G06-12（原话「**太长时间用户不在 不如像是一个老朋友一样 只是道一句 好久不见**」）
- 适用版本：v0.1 起
- 影响：**Q026 表里 ④「时间到了」的边界（不是推翻，是划清）**、F06-9、F06-2、F06-5、D051、D054、术语表

**这条和「凭时间开口」的关系，必须先说清，否则会被当成 ④ 复活**

- 「好久不见」**确实是凭时间开口**。如果就这么放进去，等于在 ④ 的封条上开一个口子，以后谁都能说「我这个也算缺席触发」。
- 区别只有一个，但足够硬：**④ 是日历周期，它是缺席事件。**
  - ④ 每天都会到，所以每天都要说一句，剩下的日子只能填套话——**套话第一周是温暖，第十天是噪音**（Q026 已写死的死法）。
  - 「好久不见」以「他真的离开过一段」为前提，**同一段缺席只触发一次**，说完就没了。它不产生周期性输出，因此没有「填不满的日子」这个问题。
- **所以 ④ 的禁令改写为**：**禁止一切「按日历重复」的开口；允许「因状态变化而一次性」的开口。** 判据是：**这段话会不会在明天、后天、大后天以同样的形式再来一次？会，就是 ④。**

**四条边界（缺一条就会变成查账）**

1. **不问去哪了。** 不说「好久没来了」「最近忙什么」「是不是把我忘了」。**他一回来就被问行踪，等于补交缺席说明。**
2. **不道歉、不表功、不制造亏欠。** 禁止「抱歉这么久没联系你」（软件不是人，道歉是假的），禁止「我一直在等你」（**这句最毒——它把等待变成他的人情债**）。他价值观里最要紧的一条是「我不亏欠」，任何让他觉得欠了什么的措辞都不能用。
3. **只说一次，不叠加。** 走五天是这一句，走十个月也是这一句。不说「好久好久不见」，不说「都快一个月了」——**一旦开始报天数，它就变成了记账。**
4. **说完就停。** 不接「这段时间有没有什么想聊的」，不问「要不要看看你之前说的那件事」。他接话就正常聊，不接就到此为止（不追一句「在吗」）。

**阈值**（`[助手默认]`，可改，但不给界面入口——D021 零维护，多一个参数就多一个要维护的东西）

- **≥ 5 天**没说话（以最后一次对话距今计）→ 触发。
- **1–4 天**→ 不触发，按正常接续处理（这几天的缺口由 F06-2 的 ②③ 和 F06-5 的延后管，不归这条）。
- **不因缺席时长分档**：五天和五十天说的是同一句话。

**它和打扰的关系：它不是打扰**

- **它是会话开场，不是推送。** 只在**他打开窗口／发出第一条消息**时出现在对话流里，**不做系统通知、不消耗配额、不受打扰总开关管辖**。
- 理由：打扰是「它在他不在的时候找他」；这一句是「他回来了，它接住」。**他已经在场了，就不存在打扰。**
- **回来的当天，F06 的三类触发全部冻结**（约定、未完的事、没闭合的状态都不发），次日恢复。**不清算。** 他一回来就收到「后天那个谈完了吗」，那句「好久不见」就白说了。
- **缺席期间攒下的「待延后」消息，同样不在当天发。** 次日再判时效：还成立的送一次，已过时的删掉，全程不提「你不在的时候有几条」。

**它不会说的话（写进 `SOUL.md` 的措辞负面清单）**

| 禁止 | 为什么 |
| --- | --- |
| 「你终于来了」 | 撒娇／埋怨，把缺席变成他的过错 |
| 「好久没见，最近是不是很忙」 | 问行踪，是查账的第一句 |
| 「这段时间我一直在想你」 | 制造亏欠 |
| 「距离上次聊天已经 12 天了」 | 报天数＝记账 |
| 「欢迎回来，今天想做点什么」 | 客服腔，且立刻派活 |

- 关联：Q026（④ 的边界）、D043、D048、D051、D054、D058、D022、D033、F06-2、F06-5、F06-9

- **为什么弹窗装不下了**：原来那六个输入框是「填两个字符串」的量级。而模型一旦要说清「有哪些服务商、各自有哪些模型、现在用哪个」，弹窗那个高度就变成了**把一份配置硬塞进六个格子**——塞不下就会开始省略，而省略掉的正是「这个模型的上下文是多大」这类会影响行为的字段。
- **为什么要照 opencode，而不是自己发明一套**：它的格式已经在真实项目里被用了一年多，**有现成的 `$schema` 可以校验、有 `{env:}`／`{file:}` 两种「key 不写进文件」的写法**、而且外面的人不用学第二套。仿一套自有格式，代价是每次都要自己解释一遍，收益是零。
- **五条 [助手默认]（他能一句话推翻，但推翻要连带改实现）**：
  1. **JSON 是唯一的源**。`baseUrl`／`apiKey`／`model`／`contextWindow` 全部由它算出来，不由人直接填。留两个源就一定会对不上，而对不上的时候**程序不报错，它只是在错的地址上说话**。
  2. **派生值不落盘**。`config.json` 里只存 `modelConfig`（占位符原样保留），那四个值每次读配置时现算。要是保存时展开一遍再写回去，`{env:}` 就白写了——key 又躺回明文文件里。
  3. **整份拒写**。校验不过就抛，**一个字段都不写**。半写是最坏的结果：JSON 是新的、地址是旧的，照样能跑，只是答得不对。
  4. **坏了宁可空着**。`modelConfig` 在但解析不通时，`baseUrl`／`model` 置空并把 `modelBroken` 标上，**绝不退回默认地址**。空地址会当场报「还没有填 API 地址」；默认地址能让它带着一个错的模型名正常工作。
  5. **老配置给一份 seed**。只有手填三字段的老配置，界面第一次打开时用 `seedFromLegacy()` 生成等价 JSON 填进编辑器，**只在内存里生成、不落盘**——他没点「应用」之前，配置一个字都不该变。
- **兼容 opencode 的两样东西**：`{env:变量名}`（没设时按空串，但**必须说出是哪个变量**，否则他只会看到一个 401）与 `{file:相对路径}`（相对配置文件目录，和 opencode 一致）。导入 `.jsonc` 时去注释和尾逗号——opencode 两种都吃，照做，否则别人贴过来的配置会白报错。
- **只认 OpenAI 兼容协议**：`npm` 字段写别的包名（如 `@ai-sdk/anthropic`）不报错但**发警告**——本应用只会说一种协议，照它想的跑不了，不说清楚就是让他自己 debug。
- 边界：`$schema`、`tools`、`mcp`、`agent` 这些 key **认识但不处理**，原样留在 JSON 里。认不认识是两件事：认识所以不当成错误，不处理所以不当成功能。
- 代价：以前「复制一个地址、粘一个 key」就能用，现在要么会写 JSON，要么得从文件导入。**这是他自己选的交换**——换来的是「现在到底在跟谁说话」有一份能看、能存、能贴给别人的账。
- **适用版本修正（2026-11-05，见 D076）**：顶层 `model` 现在只是链的第一项，整条顺序记在 `x-hundun.modelOrder` 里；「JSON 是唯一的源」这个结论不变。

### D076 多个模型排成一条链，按顺序试
- 内容：设置里可以放**多个**模型，**从上到下就是尝试顺序**。第一张是现在用的；它连不上就换下一张。拖动卡片，或者用卡片上的「先用／↑／↓」改顺序，点一下立即生效，不用再点保存。
- 状态：已确认（方向）｜**[助手默认]（下面四条）**
- 确认人：用户｜确认方式：原话｜确认日期：2026-11-05
- 来源：G12。原话：**「允许用户配置多个模型 同时排序 优先使用排在前面的模型 可以参考cc-switch的首页」**
- 适用版本：v1 起
- 影响：`models.js`（`chain`／`orderOf`／`withOrder`／`moveModel`／`addModel`／`removeModel`）、`llm.js`（`chainOf`／`runChain`）、`store.js`（`modelChain` 派生）、`index.js`（`cfg:modelEdit`）、`preload.js`、`SettingsPage.vue`（卡片链）、`styles.css`；P-34
- **为什么要有多个**：不是为了回答更多样，恰恰相反——**是为了在主力不行的时候还能说同一种话**。一个模型挂了、限流了、key 过期了，它不该就此闭嘴。所以这里排的是**备用链**，不是候选池。
- **顺序存在 `x-hundun.modelOrder` 里，顶层 `model` 是它的第一项。** 为什么不把顺序单独存进 `config.json`：那会变成两个地方各记一次「先用谁」，而两者对不上的时候**程序不会报错，它只是用的不是他排的那个**——这个项目里已经有过两次同类故障。写入时两个值永远一起重算，所以不存在两份互相矛盾的事实。
- **手改顶层 `model` 仍然立即生效**：它会被提到第一位，其余备用按原顺序跟在后面。否则「改了 model 却没反应」——那是最难查的一种错。
- **四条 [助手默认]（能一句话推翻，但推翻要连带改实现）**：
  1. **已经推过字就不换。** 换了会显示成两个模型的话拼成一段，而接缝在哪没有任何人看得出来。这是整条链最要紧的一条规则，单独抽成 `runChain()` 就为了能验证它。
  2. **超时不换。** 超时说明网络这一层有问题，换一个地址大概率同样超时，代价是把「卡三分钟」变成「卡九分钟」。
  3. **换了要说出来。** 界面上给一句「DeepSeek Chat 没连上，这条是 Qwen2.5 7B 回的」。悄悄换掉的话，同一句回答的口气突然变了，而他找不到原因。
  4. **降级不等于切换。** 第一张卡片不点就不变，下次仍然先从它试。备用是「这一次它不行」，不是「以后都换掉」。
- **和 cc-switch 的关系**：界面形态照它——一列卡片、当前生效那张有标记、操作按钮悬停才出现、配置文件退到后面。**但语义不同**：cc-switch 是「同一时间启用一个」的手动切换器，这里是一条自动往下掉的备用链。
- **每条卡片能单独测。** 底下那个「测试连接」只测首选；而备用模型最常见的问题是「配了但从没通过」——等主力真挂了才发现备用也不通，那就等于根本没有备用。
- 代价：多了一个自动行为。防线就是上面第 1、3 条：不能拼出两段话，也不能悄悄换。
- 关联：D072、F12、P-34

  1. 窗口可见 → 算送到；
  2. 窗口不可见 → 弹系统通知，**只有收到 `show` 事件才算送到**。`show()` 调用成功不算——没有通知守护进程的桌面上它一声不响地什么也不做，把它认成送到，这条约定就永久结案了。D057 只允许往「多问一句」的方向错。
  3. 既不可见、通知也没弹出来 → **不标记已问**：时效弱改成 `待延后`，时效强直接删行（F06-27）。
- **四条 `[助手默认]`（可一句话推翻，但推翻要连带改实现）**：
  1. **两条之间至少隔 10 分钟。** 「一次只说一件事」不等于一分钟说一件；三条同时到期连着弹三次，读起来就是催收（F06-5 硬上限 2 要防的正是这个）。
  2. **启动后等 20 秒再判第一次。** `ready-to-show` 之前窗口还不可见，那时判送达只能靠通知：他会先收到一条通知，点开才发现窗口里早就有一句话。
  3. **时效第一版用关键词判，默认强。** 强词（谈、开会、面试、交稿……）优先于弱词，所以「跟客户谈项目细节」不会被「项目」拖进 weak。认不出来的一律当强、也就是过时即删——**少问一句只是少一句，多问一句是打扰**。P-13 会换成真正的判断，换的时候必须保住这两条。
  4. **配额只在「未问 → 已送达」时加一次。** 待延后的补送不占配额（F06-5 硬上限 3），生成失败也不算一次。
- **生成失败（没 key、网络不通）什么都不标**，只压 10 分钟冷却。这不是「没送到」，是这句话压根没说出来；标成待延后会让它下次重说一遍，而他从没听过第一遍。
- **两轮对话互斥**：它自己开口的那几秒里他按回车，这一轮直接拒掉，**并把话还回输入框**（不清空）。两轮同时跑会共用一个 `history`，字串成一段而且接缝看不出来。
- 代价：窗口不可见时，即使通知弹出来他也可能没看见 —— 判成已送达就结案了。这是 D057 明确接受的方向：**错在少问一句**。

### D079 用户档案写成要求；记忆写入是覆盖，不是追加

- 内容：`USER.md` 从「访谈问卷」改成**指令清单**，`<profile>` 从「往访谈实录追加流水账」改成「同主题覆盖」。同时给所有记忆写入加三道闸。这是 D078「工程做法照搬」的第一批实质落地。
- 状态：已定（2026-11-05）｜已落：`src/main/life.js`（`ingestProfile`／`appendLongterm`）、`src/main/conversation.js`（`persistNotes`）、`src/main/schedule.js`（传 `provenance`）
- 确认人：用户｜确认方式：原话「那现在要做的事 就是把openclaw已有的东西往我这壳子里搬」「用的gateway 但是我们不用」｜确认日期：2026-11-05
- 来源：openclaw `docs/reference/templates/USER.md`（user-model 契约）、`docs/concepts/memory-architecture.md`（tier model／write path／user model）；其引用的 PrefEval（ICLR 2025）

**一、档案写的是要求，不是观察**

`「他喜欢简短」是观察，「回答保持简短」才是要求`。观察只是上下文里的一句话，读过就淡了；要求会被当成指令执行。openclaw 的用户模型契约就是这条，不是文风问题——它的依据是：**偏好被读进上下文几轮之后就开始失效**，唯一稳的办法是把它写成可以直接执行、且能在需要时被重新说出来的句子。

结构因此改成两节：
- **`## 关于他`** —— 事实（怎么称呼、在做什么、作息）
- **`## 要求`** —— 他对你怎么说话的要求

每条写成 `<!-- observed: 日期 | status: active -->` 换行 `- [主题] 正文`。

**二、覆盖，不追加**

原来同一个偏好说三遍就是三条，前后矛盾也不合并。openclaw 的做法是**改了主意就改原来那条**，旧的标 `superseded` 留在原地（看得见他是怎么变过来的），绝不并列两条相反的 active。

理由是实测的失效模式：**追加式偏好历史会让模型从旧值回答**。三条互相矛盾的记录摆在一起，它不会挑最新的。

判定顺序：
1. 一字不差 → 跳过（见下面第三道闸）
2. 同主题（模型给的 `主题｜内容`），或意思相似度 > 0.75 → 旧的标 `superseded`，新的紧接其后
3. 都不沾 → 新增

**三、三道写入闸**

1. **召回防回环**：`USER.md`／`MEMORY.md` 每轮都在上下文里，模型很容易把**读到的**当成**新发现的**再输出一遍。不拦的话同一个事实每聊一次加一行，一个月后真话被埋在复读里，而它自己会开始照着复读答。判定用**严格相等**（去空格标点后全等），不用相似度——`别用 emoji` 和 `别用emoji表情` 是带新细节的重述，当重复丢掉就永远补不回来。
2. **会话类型闸门**：它自己开口那一轮（调度器发起）**一个字都不记**。理由不是洁癖：那轮里的话全是它生成的，他一个字没说；记进去，明天它就会读到「我说过他最近在忙 X」，而 X 是它自己编的，从此当事实用。照 openclaw 的 session-kind gating，用 `provenance: 'scheduler'` 表达，不用 `internal`（后者只管「不进历史」）。
3. **相似度分母用并集**：用「较小那条」的话，短句正好是长句前缀时恒等于 1 ——「别用 emoji」会把「别用emoji表情」吃掉。已踩过。

**四、没照搬的部分（gateway 与 Electron 的差别）**

- **SQLite 记忆索引 / 后台 worker / dreaming 三阶段**：都是 gateway 侧的常驻服务。Electron 单进程里搬不动，也不需要——索引这边已有 `sql.js`（`search.js`）。但 dreaming 的**目的**要留（定期把日记折叠进长期记忆），实现另说，见待搬清单。
- **provenance 四分类**（`owner`/`agent`/`untrusted`/`system`）：一期只有一个本地用户、没有外部内容源，两档（`user` / `scheduler`）够用。字段名留好，等接搜索或多渠道再扩。
- **每条偏好做 embedding 语义去重**：不做，用主题键 + 二元组相似度。主题键是确定性的，比向量稳，也不花钱。

**五、代价**

- 主题靠模型给。它不给就退化成相似度匹配，可能把两条不同的要求误合并。
- 覆盖会把「改主意」和「换个说法重说」当成同一件事，旧条目靠 `superseded` 保留可追溯。
- 0.75 这个阈值是拍的，没有语料支撑。真出问题再调，不要现在为了调它引入复杂度。
- 老 `USER.md` 只升「还空着」的那份；已经有内容的原样保留——把流水账翻译成要求是语言判断，代码做不好，硬转会把他写的话揉坏。

- 关联：D028、D061、D077、D078、F06-04、P-09、P-13

### D080 记忆折叠：日记会自己缩，但它一句话都不说

- 内容：新增 `src/main/dream.js`，把攒够的日记定期提炼进 `MEMORY.md`。这是搬迁台账 P1，照 openclaw 的 dreaming **只搬了目的**。
- 状态：已定（2026-11-05）｜已落：`src/main/dream.js`、`src/main/index.js`
- 确认人：用户｜确认方式：上一轮建议「搬 P1 记忆维护」，用户回「1」｜确认日期：2026-11-05
- 来源：openclaw `docs/concepts/dreaming.md`、`docs/concepts/memory-architecture.md`「Dreaming: consolidation with gates」
- 适用版本：v1

**要解决的是什么**

日记只增不减，`MEMORY.md` 也只增不减。跑三个月，`MEMORY.md` 会变成第二份日记——于是它每一轮都要读一大堆「今天很累」「今天卡住了」，真话被埋在流水账里。**这不报错、不崩，只是它越来越像在背流水账。**

**搬过来的三个判断，一个没省**

openclaw 是三阶段（light 暂存 → REM 反思 → deep 晋升）+ SQLite 召回计数 + embedding 聚类。那些是 gateway 侧常驻服务，Electron 单进程搬不动也不需要。但它的三个判断是文件层的东西，全搬了：

1. **晋升要有门禁**，不是「日记里出现过就升」。它的门禁是 `minScore`／`minRecallCount`／`minUniqueQueries`（同一件事被反复提到、被不同问题问到才算数，长这样是因为 LongMemEval 那类评测显示「写得准」比「索引得好」重要得多）。这边没有召回计数，用更笨但更稳的办法：**一次喂好几天的日记，让它在跨天的尺度上判断**——单天的情绪自然落选。
2. **模型只做语言判断，门禁是代码。** 哪些话值得留，模型判断；喂哪几天、一次最多几条、和已有记忆重不重复，代码管。
3. **失败退回保守路径。** 调不通就什么都不写、进度不推进，下次重来。绝不「尽力而为」地写半截。

**触发条件**

- 攒够 **3 天**才折（少于这个数几乎全是当天情绪）
- **今天和昨天不折**——它们本来就在上下文里，提炼一遍只是把同样的东西抄进 `MEMORY.md`
- 一次最多折 **7 天**（第一次跑时前面可能堆了半个月）
- 每小时看一次，启动后等 90 秒（开机那几分钟事多）
- **他正在等一句话时不抢网络**（`isBusy`）

**它绝不开口**

这个模块不碰窗口、不推事件、不弹通知，做完只写一行日志。借机说一句「我把你的记忆整理好了」就是把它变成流程——那正是 D049 否掉的东西。测试里有一条专门断言它：`折叠的结果里没有一句话`。

它也**独立于调度器**。两者的判据和产物都不同：调度器的判据是「有一条还没合上的话」，产物是**跟他说话**；折叠的判据是「日记攒够几天了」，产物是**写文件**。塞进同一个模块迟早会写成「整理完了顺便告诉他一声」。

**进度记在 `.dream.json`**

`{ lastDay, at, runs, lastItems }`，和 `.session.json` 同级、同样的原子写（`.tmp` + rename）。读不出来就当没跑过——宁可多折一次（`appendLongterm` 会去重），不能因为一个坏 JSON 停摆；反过来，为了写状态把已经提炼出来的东西丢掉才是真亏。

**一个刻意的选择：空回复要推进**

模型对「这几天没啥可留的」有两种反应：不输出块，或者一个字不说。如果后者当失败、不推进，**那一天的日记就成了路障**——后面所有新日记都堆在它后面永远折不到。所以空回复也推进，只记一条日志。

真正的失败（网络、鉴权、超时）是抛错的，走 catch，一条都跑不掉。

**代价**

- 看不到折叠了什么。只写日志，没有 `DREAMS.md` 那种审计文件。真出问题要翻 `MEMORY.md` 的改动。
- 门禁靠「跨天」这个笨办法，没有重复计数。今天说了三遍的事和只说一遍的事，权重一样。
- 3 天／7 天／6 条都是拍的，没有数据支撑。

- 关联：D028、D049、D077、D078、D079、P-10、`06-OPENCLAW-PORT.md` P1

### Q026 「一句问候／一句加油」能不能自己开口？

- **裁决：D022 有效，但它的实现方式变了。** 旧解法是 §1.6 第二条写的「让忽略零成本」（忽略不追问、不记账、下次照常）；新解法是**在他自己划定的窗口内才会发生**——允许时段是闸门，日配额是上限，「今天别烦我」是当天作废。**他从「不许打断我」变成了「打断我的窗口由我划」。**
- 为什么新解法更好：旧解法只能靠软件自律（它承诺不追问），新解法是**结构性的**（时段之外物理上不可能触发）。**结构性约束优于承诺。**
- **仍然残留的张力（诚实标注）**：约定到期那天，他恰好处于「不想被任何人找到」的状态，而窗口正好开着。此时他只有两个动作——点「今天别烦我」，或者不管它。**后者在 D029「使劲补」之下不会被追，但那条约定会悬在那里**（→ Q022 的「没回应」分支）。这个场景没有完美解，只能靠措辞。
- 影响：§1.6 第二条的表述需修订、F06、F08、Q022

### X-10 约定追踪 vs 「不评判、不记账」
- 来源 A（D033，用户 G06-2）：伙伴的三条可判定性质——在场／记得／不评判。D044 进一步要求「对内理性必须能对应到一个『因此我说／不说什么』的动作」。
- 来源 B（D043，用户 G06-7）：它会记住「后天要谈」并在后天来问。
- **G06-8 已裁决（部分）**：D050 给出落空之后的做法（先哄 → 给一个可拒绝的复盘入口 → 不想就不复盘、不留记录）。四条红线**全部保留**，改为**已确认**，不再需要他再点头。仍未覆盖的只剩一件事：**「不复盘」时它会不会偷偷把这次记成教训**——D050 限定第 3 条写死了不许，但这一条只能靠验收（F06-17）查，设计上无法保证。
- 冲突性质：**这是本 PRD 曾经最危险的一处真冲突。** 「记住约定并到期回访」与「不记账」在结构上非常接近，只隔一层薄薄的意图：**关心与追债在外部行为上长得一模一样。**
  - 关心：问一次，听你说完，结案。
  - 追债：问一次，你说没做，它记下来，下次再问，或者你的「未完成」开始累积成一份清单。
- ~~**未裁决。** 裁决点全部集中在 Q022~~ → **Q022 已答（G06-8），用户对四条红线的原话是「四个红线好」。** 以下四条由 `[建议]` 转为**已确认**：
  1. **一条约定只问一次。** 问过就算用过，无论结果如何，**永不重提**。
  2. **不做跨约定的汇总。** 不许出现「你最近三个约定有两个没兑现」这类判断——那怕只是在内部算出来，也违反 D044 的判据（它对应不到任何输出动作）。
  3. **不自动续期。** 约定结束即结束，新的约定只能由他下次开口（否则滚成待办清单）。
  4. **「没回应」＝「不想再提」，不是「没做到」，也不是「没看见」。**（**G06-10 强化，落 D054**）不记为失败、不补问、不换措辞、不换通道、不借别的话头再问。原表述是「不回就是不用管」，把沉默读成中性；**他也是这个意思，但更狠：沉默是有含义的拒绝。** 中性解读会导出「换个时间再试一次」，拒绝解读不会。
- **为什么这条红线必须先立**：这四条拦住的是「伙伴悄悄变成 KPI」的那条路。而一旦走上去，**回不了头**——用户发现自己被统计的那一刻，前面所有的温柔都变成表演。

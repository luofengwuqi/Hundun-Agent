## 1. 产品定位与范围

> **独立应用的定位（D013，2026-11-04 重申）**：它自己持有窗口、进程、模型连接和本地数据，**不依托任何平台运行**，也不作为任何平台的插件、技能、专家包或小程序分发。
> 文档里若还出现「在某个宿主平台内跑」一类说法，那是**已被 D013 取代的早期方案**（D001、D011，均已作废），不是设计，不要照着它写代码。

### 1.1 一句话

一个只在你本机运行、记忆写在你自己能读能改的 Markdown 文件里的桌面**伙伴**。它记得你昨天说过什么——记得的是你的原话，不只是它的总结；只在你**答应过的事到期**时提一句（不按钟点、不打卡）；用你给它的模型接口说话。[已确认：D002、D008、D013、D017、D028、D033]

**它的入口和出口是明确的。** 你点进来的时候，通常是**迷茫**或**疲惫**的；你走出去的时候，必须落在「**知道了接下来做什么**」或「**心里松了一点**」其中一边。两样都没有，这次就没成。[已确认：D031、D032]

「伙伴」不是形容词，是三条可判定的性质：**在场**（不需要你召唤也在）、**记得**（能回指到日期和原话）、**不评判**（记下失败但不追究、不索要解释）。[已确认：D033]

它不是助理、不是待办工具、不是知识库、不是教练。它不替你干活，不向你索要进度，只跟你说话。[已确认：D008、D010、D033]

### 1.4 成功判据

本产品**不设事前量化验收门槛**（D030）。用户原话：「第四个问题我觉得不重要 先把东西做出来我自己用的时候不舒服就会去修的」。因此本节不给通过／不通过的门线，只给两条随时能自查的东西：

1. **单次会话的出口判据**（D032，唯一一条每次都生效的）——聊完之后，你要么知道了接下来做什么，要么心里松了一点。两样都没有，这次就没成。这条比任何全局门槛都更适合自用场景，因为它每次都能立刻验证。
2. **三条稳定性自查项**（原 Q015 的判据，已降级为参考，**不是交付门**）：
   - 长时间常驻不重启，进程不退出、不卡死，内存不单调爬升；
   - 强杀进程后重启，记忆文件与强杀前一致，不出现半截文件、不丢已写记录；
   - 断网、Key 失效、接口 500、返回非 JSON 四种情况下，只报错、保持可用，不崩、不卡在「生成中」。

这三条不是「达标才发货」，而是「哪天觉得不对劲时拿来对照」。**D024（稳定优先于功能）仍然有效**——取消的只是「用文档宣布达标」这个动作，不是取消稳定性本身。

### 1.6 七条一等约束（能覆盖其他决策）

这七条性质与普通需求不同：**遇到冲突时默认按它们取舍，不需要再逐条确认。**

1. **零运维**（D021）。用户上一个记录工具死在这里——一个 Web 应用，服务太多、起不来。所以本产品不得要求他自己维护任何东西：不起服务、不装数据库、不配环境变量、不先启动别的进程。凡引入一个「你得先把它跑起来」的部件，就等于在最容易复发的地方重新埋雷。
2. **随时拿起来，随时放下**（D022）。打开就是对话，不用选会话、不用等初始化、不用登录；关掉不丢东西，也不需要「先收个尾」。这条与「主动找你」「错过就补」有张力。**G06-7 之后张力的解法变了**：旧解法是「让忽略零成本」（软件承诺不追问、不记账），新解法是**「打断的窗口由用户自己划」**——允许时段是闸门，日配额是上限，「今天别烦我」当天作废（D045）。**结构性约束优于承诺**：时段之外物理上不可能触发，不依赖软件自觉。残留场景见 X-09。
3. **稳定优先于功能**（D024）。出现「加这个功能」与「保稳定」的取舍时，默认选稳定。判据不由文档预设，交给实际使用（D030）。
4. **伙伴关系优先于功能完整**（D033）。任何使「它像工具」的设计都要让位——要你填表、要你打卡、要你汇报进度、要你解释为什么没做到，都属于这一类。这条比前三条更直接地决定了「用不用得下去」。
5. **不重复实现系统已有的能力**（D037，G06-4 新增）。凡「要不要在应用里做某个视图／编辑器／预览／文件管理」，先问操作系统的文件管理器或系统工具是否已能做到。若已能，默认不做，**只做「打开它」的入口**。
   - 这条来自一次具体失败：记忆面板被砍（D037）。它自建了文件树＋查看器＋编辑器＋搜索，增量只有「不用切窗口」，代价是三个组件、两个 IPC 通道、一整套并发写冲突，以及一个用户不知道存在的入口。
   - 边界：它管的是**重复造 UI**，不管后台能力。F05 后台检索不适用本条——人看不见它，它也不重复任何系统功能。
6. **不预设用户没给过的具体参数**（G06-5 新增，这是最硬的一条）。凡是**数值型、时刻型**的参数（几点、几次、多久、多长），只能有两种来源：用户的原话，或者用户在引导里当场给出的回答。**助手的示例值、代码里的默认值、上一版文档里的写法，都不构成来源。**
   - 反面案例：`08:30／21:30`（D016、Q017）。它在 S01 里只是助手举的一个例子，旁边助手自己写着「现在只能瞎定时间」；进了 `store.js` 之后长得像需求，被两版 PRD 当既成事实引用，最后差一点做进安装包。
   - **操作方式**：这类参数一律做成可配置，且默认值只能是「空」或「关闭」；需要初值时走 D004 的引导提问，用他的回答算出来，再经他确认。**宁可不用，不许猜。**
   - 判据：任何具体数值在 PRD 里出现时，必须能指到用户原话或引导回答。指不到的一律标 `[建议]`／`[助手默认]`。
7. **对外极度宽容温柔，对内极度理性中立客观**（D044，G06-7 新增）。人格拆成两层，**不共用同一套语气**：
   - **对外（用语）**：它对用户说出口的每一句话。标准是「极度宽容、温柔」。
   - **对内（分析用户、分析方向、分析计划）**：它怎么判断、怎么取舍、要不要说、要不要查证。标准是「极度理性、中立、客观」。
   - **两层的接口是单向的**：理性层的产出是**决策**，不是**评价**。**任何一次内部判断，都必须能对应到一个「因此我说／不说什么」的动作。对应不上的判断，就是在攒账，不许做。**
   - 这条解决的是本项目最难的一处张力：D031（要安慰）与 D023（要方向）此前只能排队（先安慰后指导）。拆层之后两者不再竞争——**温柔是表达层，理性是判断层**，温柔不牺牲判断力，理性不要求语气变冷。
   - **必须防的最坏读法**：把「对内理性」做成「在心里给他打分／统计第几次没做到／判断他是不是在找借口」。那会造出一个**礼貌的审判者**——比直接批评更糟，因为它不承认自己在评判，直接撞 D033。→ X-10

`[建议]` 这六条同时指向一个方向：**这个产品的竞争对手不是别的 AI 应用，是他自己的惰性和上一次的失败。** 因此任何让「打开它」变重的东西，优先级都低于让「打开它」变轻的东西。这条是助手的判断，未获用户明确表态。

## 4. 功能规格

> 每个模块六项：使用者、前置条件、主流程、异常流程、业务规则、可配置边界。
> 标 `[文档既定]` 的是代码现状，未经本 PRD 验收；标 `[已确认]` 的能追到 D；标 `[待确认]` 的不得当作默认值开工。

### F01 首轮访谈与档案建立

- **使用者**：**每一个新身份**（首次使用的用户，或他新建的每个 agent）——因为记忆完全不共享（D062／D063），新建 agent 必然落到这条流程上
- **前置条件**：已填入有效 API Key；`USER.md` 处于空档案状态（无按日期的访谈条目，且「（待访谈）」占位符仍在）
- **主流程** `[已确认：D004]`
  1. 用户保存设置后，若对话区为空，自动发起一次开场（内部指令，不进入对话历史）
  2. 系统提示词检测到档案为空，追加一段访谈指令：按顺序问五件事——是谁（怎么称呼）→ 在做什么 → 作息 → 在意什么 → 红线
  3. 每轮只问一个问题；问到即用 `<profile>` 块写入 `USER.md` 的「访谈实录」
  4. 五件事问完即停止，不再追问
- **异常流程**
  - 无 API Key → 对话入口不发起请求，直接打开设置弹窗
  - 用户中途关掉应用 → 已写入的访谈条目保留在 `USER.md`，下次启动重新开场，继续问没问到的项（依据：档案判据只看「有没有按日期的条目」，不看问了几个）
  - 用户自己手改 `USER.md` 删掉占位符 → 视为已填过，不再强制访谈 `[文档既定：life.js isProfileEmpty]`
- **业务规则** `[已确认：D004]`
  - 一次只问一个问题，不并列三问
  - 访谈结论只写用户真实说过的内容，禁止推测补全
- **可配置边界**
  - 五件事的**顺序与内容**硬编码在提示词里，不可配置 `[文档既定]`
  - `USER.md` 的文件结构可由用户手改，不影响功能
- **关联决策**：D004、D031、GAP-02
- **与 D031 的关系**：首轮访谈里问「你一天大概什么节奏」这类问题时，不得做成填表打分（否则就是把 D031 否掉的采集又请回来）。这是对话，不是问卷——一次一个问题，问完就往下走。

### F02 对话与记忆块写入

- **使用者**：任意时刻的用户
- **前置条件**：有 API Key；无进行中的请求（`busy` 为假）
- **主流程** `[已确认：D002、D009]`
  1. 用户提交一句话 → 推入会话历史 → **立即追加写入 `⟨身份⟩/chat/YYYY-MM-DD.md`**（D028）。先落盘再请求模型，这样即使这一轮崩了，你说过的话也不会丢
  2. 以该句为查询去旧日记检索（F03）
  3. 拼装 system prompt，附最多 48 条历史，调模型流式接口
  4. 前端逐字渲染；流式过程中把记忆块标签从显示文本中剔除
  5. 回复结束后解析 `<memory>`／`<longterm>`／`<profile>` 三种块，分别写入今日日记、`MEMORY.md`、`USER.md`
  6. 写入后重建索引（F05）
  7. 把助手回复正文（**不含记忆块**）追加写入同一份 `chat/YYYY-MM-DD.md`（D028）
- **异常流程**
  - 模型未输出任何记忆块 → 不写任何东西，对话正常完成（「空着比凑数好」）

  - `chat/` 落盘失败 → 同上，记一条失败原因，**不中断对话**（原话是补充材料，不是主链路）
  - 界面拿到的正文为空但有记忆块 → 显示「（这一轮我只记了点东西，没别的话。）」

### F06 约定与打扰

> **本节第三次重写（G06-8）。** 第一次换个可配置容器；第二次换掉触发源（时钟 → 约定）；这一次是把剩下的关卡全部走完——**约定怎么立（D049）、落空怎么收（D050）、人不在怎么办（D051）、内容多不正经（D048）**。
>
> **不变的那一条**：它不会凭空出现。**没有可说的东西，它就闭嘴。**

- **使用者**：用户（被回访的一方）
- **前置条件**：有 API Key；应用进程在运行（含托盘常驻）；**打扰总开关已打开**且至少有一个允许时段（**默认关闭、参数全空**，D047）；**存在今天到期的约定，或一个昨天没闭合的话题**
- **术语**：原「检查点」已作废。现在两个概念——「**约定**」（对话里立下、有日期的一件事）与「**未完话题**」（对话里出现过、没说结论的东西）。

#### F06-1 约定怎么立：它自己记，不问

`[已确认：D049]`

**主流程**：对话进行中，模型判断这句话是否构成一件「有日期的事」→ 是则**静默**写入约定存储 → 对话继续，**不插入任何确认、不显示「已记录」**。

- **够格的判据**（`[助手默认]`，需他否）：有**具体时间指向**（后天／周五／月底前／下周一）**且**有**具体事**。缺一个就不算——「我最近想多写点代码」没有时间，不是约定；「后天再说吧」没有事，也不是。
- **日期不确定时不猜绝对日期**（§1.6 第六条）：存相对表达 + 对话当天作锚点，到调度时再换算。
- **他纠正时的唯一正确反应**：立刻改／删，**不说话、不解释、不回忆「你当时说的是……」**。任何一次辩护都会让「它记着」从帮助变成负担（D033）。
- **我原推荐的是「当场问一句要不要记着」，他否了。** 理由记在这里，防止以后有人又把确认加回来：那条理由（「双方都知道」）是从契约角度想的，不是从对话角度想的——他聊到兴头上，软件插一句确认，就是把聊天变成流程。**代价（会记错）已知，靠上面的纠正机制兜，不靠加确认避。**

#### F06-2 三类触发源 `[D043＋D048＋D059＋Q026]`

**判据只有一句：它开口，是因为它记得你说过一句还没合上的话；不是因为时间到了。**

| | 触发源 | 判定 | 何时 | 状态 |
| --- | --- | --- | --- | --- |
| **① 约定** | 对话里立下的一件事 | 有日期 + 有具体事 | 到期日当天 | `[D043]` |
| **② 未完的事** | 对话里出现过、没说结论的东西 | `[助手默认]` 上一轮有一个悬空问句／未回应的选择／「再说吧」式收尾 | 次日，只回访一次 | `[D048]` |
| **③ 没闭合的状态** | 他上一轮说过自己不好受 | `[助手默认]` 「累」「顶不住」「睡不着」「烦」这类，且没有下文 | 次日，只问一次 | **`[助手默认]` 放行，待他裁（Q026）** |
| **④ 时间到了** | —— | —— | —— | **永久禁止**（边界见下） |

- **④ 的边界（D059 划清，不是松口）**：永久禁止的是**「按日历重复」的开口**；**「因状态变化而一次性」的开口**另有一条合法通道（缺席回来那句「好久不见」，F06-9）。判据只有一句：**这段话明天、后天、大后天会不会以同样的形式再来一次？会，就是 ④。**
  - 「好久不见」不会再来一次——它以「他真的离开过一段」为前提，同一段缺席只触发一次。

- **④ 为什么永久禁止，写一个具体的失败**：允许 ④，它每天早上都会说一句，因为每天早上都是早上。而每天没那么多「有事」的日子，剩下的只能填套话。**套话第一周是温暖，第十天是噪音，然后被关掉。** 这就是旧形态（`CHECKPOINTS.md` 早间／晚间）的死法。
- **同样是「一句加油」，两种接法的区别**：
  - 接在 ③ 上：「昨天你说有点顶不住，今天还那样吗，加油」——这是话。
  - 接在 ④ 上：「新的一天，加油」——这是打卡。
- **③ 的三条限定**（否则「问候」会滑成「例行安慰」）：
  1. **只接昨天，不接更早**。隔三天问「你前几天说累」，那是记账不是关心。
  2. **一条状态只问一次**。他说「好多了」或「还那样」即闭合，不再问。
  3. **不评估好转程度**。不问「比昨天好点吗，几分」——一旦打分就是审判（D044 判据）。
- **②③ 的现实约束**：都只在「隔了一天」这个尺度内成立。**隔了三天的不算。**

#### F06-3 主流程

`[已确认：D043、D045、D047、D049、D053、D057、D058、D061、D067]`

1. **立约定**（F06-1，静默）→ **追加一行**到 `⟨身份⟩/COMMITMENTS.md`（GAP-07 已关闭）→ **四列**：`什么事`、`到期日`、`结局`（初值 `—`）、`消息`（初值 `未问`）；**若他当场要求「到那天一定要问我」，同加一列 `pinned`**（D053）
   - **D061 修正（2026-11-04，开发期）**：原为三列，`结局` 一列同时被用来装「这件事的结果」和「这句话送没送到」，两套枚举无法共存。现在 `结局` 只管事（`—`／`成了`／`没成`／`没去`），`消息` 只管话（`未问`／`已送达`／`待延后`／`已结案`，走 P-12 状态机）。**合并会让「他不想再提」和「那晚他没开机」写成同一个词**，而 D057 的全部论证就建立在二者必须分开之上。
2. **调度检查**（→ O12）：以下七条**全部**满足才可触发——
   - 今天有到期、且 `消息` 列为 `未问` 的约定，**或**有一个昨天未闭合的话题，**或**有一条 `消息` 列为 `待延后` 且「时效还在」的消息（D058、D061），**或**有一个昨天说过、还没闭合的**状态**（「有点顶不住」「睡不着」）且昨天之后再没聊到过（**D064**，三类触发源由此定齐）
   - 当前时刻落在**某个允许时段**内（区间判断，不是等值比对）
   - 今日已发次数 < **每日上限**（不结转；延后送达同样计数）
   - 今天**未被**「今天别烦我」作废
   - **待延后的那条话，现在说仍然成立**（时效判断，F06-5）
   - **今天不是「缺席回归日」**（≥5 天没来之后回来的第一天，F06-9：三类触发全部冻结，含待延后）
   - **这条约定属于当前 agent**（**D067**）：被切走的 agent 手里的约定**不参与调度**；切回来时 `到期日 < 今天` 的直接按 F06-5 的时效判断处理，**多数情况是删，不是补问**。**「切走」不算「没送到」**——没送到是应用没开（`待延后`），切走是他自己选的跟别人说话，不延后、到期即过期。混成一件事的后果很具体：你切去 B 聊两周，回到 A 时被一口气补问五六条过期的事，那是催收不是老朋友。**唯一例外是 `pinned`**：他在立约时说过「到那天一定要问我」的那一条，**切回来仍然问一次**——这句话的意思就是「不许被任何事耽误」，换 agent 也算「任何事」。判据与 F06-31 同一条，不另立规则
3. **触发动作**：显示窗口 → 拼上下文（那条约定／话题 + 最近记忆 + 用户画像）→ 内部指令调模型 → 流式渲染 → 系统通知（正文前 90 字）
   - **不抢焦点**：通知只提示，点开才进窗口
   - **一次只说一件事**，不附带「顺便今天的计划呢」
   - **是延后送达的，措辞必须重写**，不能照搬到期那天的话（D058）
4. **送达即标记**（**不是发出即标记**，D057）：同一条只问一次、永不重提（X-10 红线 1）
   - **没送到 → 不标记「已问」**，改标记「待延后」，等下次他在的时候再送（D058）
   - **这是本节最容易被写错的一行**：如果按「发出」标记，没送到的就永远丢了，延后无从发生；如果按「渲染完成」标记，他关机时那条也会被算作问过
5. **收尾（两列各写各的，D061）**：已送达且回了 → 按 D050 处理（F06-6），**`结局` 写 成了／没成／没去**，`消息` 写 `已结案`；已送达不回 → 按 D054 结案，**`结局` 留 `—`（他没答，这不是结果）**，`消息` 写 `已结案`；没送到 → 按 F06-5，**`结局` 一律留 `—`**，`消息` 按情况写 `待延后` 或删行
6. 记忆由 F02 正常落盘

#### F06-4 四个参数（D045）

| 参数 | 语义 | 默认 | 边界 |
| --- | --- | --- | --- |
| **打扰总开关** | 总闸。**这一行在界面上必须存在且是第一行**（→ O13） | **关**（D047） | 关闭时下方三个子项**可见但不可改**（`opacity .42` + `pointer-events: none`）——「它现在不会来找你」必须看得见，不能隐藏 |
| **允许打扰的时间段** | **闸门**。不在区间内一律不发 | **空**（＝不可触发） | 可多个区间；不做跨零点区间（23:00–01:00 拆两段） |
| **每日最多打扰频率** | **配额**。用完即止，**不结转** | **空**（＝不触发） | 0 等同关闭 |

#### F06-5 送达、时效与延后 `[已确认：D057、D058，修正 D051]`

> **这一节在 G06-11 被整节换掉。** 原来的问题是「到期日落在时段外怎么办」，答案是「作废」。现在的问题换成了另一个——**「软件问了，但没送到，算什么」**。这两个问题不一样：前者是「该不该问」，后者是「问了没问到」。

**三种结局，三条路，判据只有两个：送到了没、话过没过时。**

| 送达 | 时效 | 处理 | 依据 |
| --- | --- | --- | --- |
| **已送达，他回了** | — | 按 D050 收（成／没成／没去／不想说） | D050 |
| **已送达，他不回** | — | **按「不想再提」永久结案**。不换措辞、不换通道、不借话头 | **D054＋D057** |
| **没送到，话还没过时** | 弱 | **延后一次**，下次他在的时候再说，措辞重写 | **D058** |
| **没送到，话已经过时** | 强 | **永远不说。** 不补、不攒、不汇总 | **D051（残留部分）＋D058** |
| **没送到，话已过时但事还重要** | 强且要紧 | 唯一破口：补一次（上限一次） | D053＋D056 |

**送达怎么判（`[助手默认]`，可验收，他可否）**

- **已送达**：应用在运行，且（窗口可见 **或** 系统通知已展示）
- **未送达**：应用未运行／进程已退出／系统休眠中／窗口隐藏且通知未能展示
- **已知误判**：「通知弹了但他没看见」→ 判成已送达 → 结案。**方向安全**：错在少问一句，不是多问一句。

**时效怎么判（`[助手默认]`，判法不是「重不重要」，是「这句话现在说还对不对味」）**

- **时效强（不延后）**：有明确时点、过了就变味的事——谈项目、开会、面试、交稿、当天的约定。
  - **为什么变味**：过了那个点，「谈得怎么样啦」就从「陪你等」变成「来收账」。
  - **他自己给的例子就是最硬的一条**：后天谈项目、大大后天才上线——**「后天」这个词本身已经过期了**，那句话说出来只能变成「你之前说的那个谈了吗」。
- **时效弱（可延后）**：持续中、三天后问依然成立的事——学嵌入式、写开源、健身、某个长期项目。**这类的「后来呢」是真的想知道。**

**延后不是补——这两个词必须分开，否则「使劲补」会顺着这个词复活**

| | 那件事的时点 | 动作 |
| --- | --- | --- |
| **延后** | **还没过**（话现在说仍然对味） | 下次他在的时候正常送达，一次 |
| **补** | **已经过了**（话现在说变味了） | 默认不问；唯一例外见 D053 |

**三条硬上限**

1. **延后只给一次。** 送达后不管他回不回，立即结案，不再有第二次延后。
2. **不累积。** 三条约定都没送到，**不合成一条「你有三件事」**——那是缺席审判，D051 封过的东西仍然封着。
3. **不因延后提高频率。** 每日上限（D045）不动，延时送达不额外占配额、也不额外加配额。

**两个必须顺着改的地方**

- **措辞必须重写，不能原样照搬。** 到期说「后天那个谈得怎么样啦」，延后两天就是「前两天那个谈完了吗」。**照搬等于让它露馅，也等于把过期的话硬塞进现在的时点。**
- **「到期落在允许时段外」也归这条管**：等到下一个时段再说，**但同样要看时效**——如果等到下一个时段那句话已经变味，就不说了。原来「当天没时段就放弃、不跨天顺延」的粗规则，被这条取代。

**D029「使劲补」的最终处境（D053 之后）**：不撤回，但作用域只剩上面表里最后一行——**时效模糊、事情要紧、只补一次**。

#### F06-6 落空之后：先哄，再给一个可拒绝的入口 `[已确认：D050]`

顺序是固定的，不能换、不能合并：

1. **先接住**。一句软的，不评价、不分析、不给建议。
2. **停一下**。
3. **给入口，且只给一次**：问他要不要说。**他说不说都算结束。**
4. **不想说 → 这件事到此为止。** 不留记录、不进 `MEMORY.md` 当「失败案例」、下次不引用本次。

| 他的回答 | 它做什么 | 它不做什么 |
| --- | --- | --- |
| 「谈成了」 | 接一句，可以顺势问下一步 | 不问「那接下来几天怎么安排」 |
| 「黄了」／「没谈成」 | 先哄 → 问要不要聊 | 不分析原因、不问下次什么时候、不自动续期 |
| 「不想说」 | 收住，结案 | 不追问、不隔天再问 |
| 「没去」 | 同样不追问 | 不猜是忘了还是故意躲（§1.6 第六条） |
| **已送达**，完全没回应 | **按「他不想再提」结案**（D054＋D057） | 不补问、不记为失败、不换措辞、不换通道、不借别的话头、界面无任何痕迹 |
| **没送到**（关机／休眠／应用没开） | **不归这节管** → 按 F06-5 判时效（D057、D058） | 不当作「他没回」，不结案、不记失败 |

- **「哄」的边界**（写进 `SOUL.md`）：允许安慰，**不许空泛夸奖**（「你已经很棒了」「换成别人早崩了」）。**具体的安慰有效，笼统的夸奖无效。**
- **最容易被违反的不是「哄」，是「不记账」。** 哄人容易，不记账难——他不复盘，这件事就不能以任何形式沉淀成「教训」。
- **第三步的入口只能开一次（D054）。** 他说「不想说」或**送达后干脆不回**，都算结案。**不隔天再问一句「昨天那个还难受吗」**——那是同一个追问的第二次尝试。
- **「不回」要成立，先得送到（D057）。** 他关机那会儿消息根本没弹出来，那不算「不回」——这种情况归 F06-5，可能延后，也可能就此作废，但**绝不能被记成一次拒绝**。

##### 追问的三种伪装（D054，全部禁止）

| 伪装 | 样子 | 为什么是追问 |
| --- | --- | --- |
| 换措辞 | 今天「谈得怎么样啦」没回，明天「昨天那个事后来呢」 | 同一次追问的第二次尝试 |
| 换通道 | 对话里没回，改用系统通知再发 | 通道不是新的机会 |
| **借别的话头** | 聊别的时顺一句「对了那个谈完了吗」 | **最像聊天，也最伤人**——它假装不是追问 |

#### F06-8 异常流程

- **休眠跨过到期时刻、唤醒后仍当天** → 补送一次（这属于送达失败后的当场重试，不是「补跑」）
- **休眠跨天、唤醒后已过时效** → 直接删，不送、不提

#### F06-9 缺席之后：只道一句「好久不见」 `[已确认：D059]`

> **这一节补的是「隔了很久才回来」这个场面。** 它不是打扰的一种，是**开场**的一种——他已经回来了，就不存在打断。

**触发**：距最后一次对话 **≥ 5 天**（`[助手默认]`），且他**打开了窗口或发出了第一条消息**。

- **只在他在场时出现**：写进对话流，**不做系统通知、不消耗配额、不受打扰总开关管辖**。打扰是「他不在时它找他」，这一句是「他回来了，它接住」。
- **1–4 天不触发**：这几天的缺口归 F06-2 的 ②③ 与 F06-5 的延后，不归这条。
- **不因时长分档**：五天和五十天说的是同一句，不说「都快一个月了」（D059 边界 3）。

**当天冻结打扰（关键）**

- 回来的这一天，F06 的**三类触发全部不发**（约定／未完的事／没闭合的状态），**次日恢复**。
- 缺席期间攒下的「待延后」消息**同样不在当天发**；次日再判时效——还成立的送一次，已过时的删掉。
- **全程不提「你不在的时候有几条」**。他一回来就收到「后天那个谈完了吗」，那句「好久不见」就白说了；而报条数等于补交缺席说明。

**内容边界（写进 `SOUL.md` 的措辞负面清单）**

| 禁止 | 为什么 |
| --- | --- |
| 「你终于来了」 | 撒娇／埋怨，把缺席变成他的过错 |
| 「最近是不是很忙」 | 问行踪，是查账的第一句 |
| 「我一直在等你」 | **制造亏欠**——把等待变成他的人情债（他价值观里最要紧的是「不亏欠」） |
| 「距离上次已经 12 天了」 | 报天数＝记账 |
| 「欢迎回来，今天想做点什么」 | 客服腔，且立刻派活 |
| 「抱歉这么久没联系你」 | 软件不是人，道歉是假的 |

- **说完就停**：不接「这段时间有没有想聊的」，不问「要不要看看之前那件事」。他接话就正常聊，不接就到此为止（**不追一句「在吗」**）。

### F07 上下文压缩前静默写记忆

- **使用者**：系统
- **前置条件**：会话历史长度 ≥8 条，且估算 token 数 ≥ 设定窗口 × 0.6
- **主流程** `[已确认：D002、D009；机制来自 D013 的保留理由]`
  1. 每轮对话开始前估算当前占用（system prompt＋全部历史，中文按 2 字符 1 token 估）
  2. 超阈值时，取最近 24000 字符的历史做摘要请求（非流式，温度 0.2）
  3. 要求模型只输出两部分：记忆块 ＋ 「摘要：」开头的 200 字摘要
  4. 记忆块照常落盘 → 摘要追加到会话摘要 → 历史只保留最后 6 条
  5. 界面提示「聊得有点长，压缩了 N 条旧消息——该记的已经先写进记忆了」
- **异常流程**
  - 摘要请求失败 → 抛错，**整轮对话失败**（不是跳过压缩继续聊）`[文档既定]` → 这是设计缺陷，见下
  - 历史不足 8 条 → 不压缩，即使 token 超了
- **业务规则** `[已确认：D009]`
  - 压缩前必须先把该记的写下来——这是「先落盘再丢」的顺序，不能反
- **可配置边界**
  - 上下文窗口大小可在设置页改（默认 32000），压缩阈值固定为它的 60%，不可单独调
  - 压缩后保留条数（6）与摘要长度（200 字）硬编码
- **关联决策**：D002、D009、D013
- **已知缺陷**：摘要只存在内存，不落盘；压缩失败会使整轮对话不可用。均未列入本期修复，记为 `[后续]`。

### F08 人格与工具边界

- **使用者**：系统（作为提示词）
- **前置条件**：`SOUL.md` 存在
- **主流程** `[已确认：D008、D010、D032、D033、D044]`
  1. 每次对话把 `SOUL.md` 注入 system prompt 最前段
  2. **人格拆两层，提示词里必须分开写**（D044，G06-7 新增）：
     - **对外层（说出口的每一句话）**：极度宽容、温柔。说话短、不用「首先/其次/总之」、不用 emoji、不过度安慰、该顶时顶、一次只问一个问题
     - **对内层（怎么判断）**：极度理性、中立、客观。判断方向是否可行、这句话该不该说、这条信息要不要查证、这个约定该不该立
     - **接口是单向的**：理性层的产出是**决策**，不是**评价**。**任何一次内部判断，都必须能对应到一个「因此我说／不说什么」的动作。对应不上的判断，就是在攒账，不许做。**（→ X-10）
  3. 边界约束：只能读写 `~/life/`，不执行命令、不碰其他目录。**网络只有一条出口**：拿不准的外部事实可以查（D052 / F09-A），除此之外不发任何请求；**不得把他的原话当搜索词**
  4. **入口态判定**：用户发起的对话，默认对方迷茫或疲惫，不追问「你怎么了」，也不假装没看见。**打扰发起时不适用**（见 F06-2）
  5. **出口收敛**：每次会话结束前，必须把话收到「接下来做什么」或「这样也行」其中一边。两者都没有，这一次算没成
  6. **伙伴关系的三条性质**在提示词里显式写出：在场（不需要召唤也在）、记得（引用要带日期与原话）、不评判（记下失败但不追究）。**G06-7 之后「记得」第一次有了可见证据**——约定回访（D043）：只有真记得，才可能在后天问出那句话
  7. **称呼**：可称「芜柒」（用户示例里的自称）。称呼属于人格偏好，存 `USER.md`／`SOUL.md`
- **异常流程**
  - `SOUL.md` 被删 → 注入为空，人格退化（不会崩，但说话方式随之失控）
  - 模型不遵守边界 → **技术上已经不可能越界**：模型没有工具调用通道，只能输出文本与记忆块，写盘由主进程执行 → 边界从「提示词约定」升级为「硬隔离」
- **业务规则** `[已确认：D032、D033、D044]`

  **内外分层的判据（最关键的一条，写在提示词里）**
  - 「对内理性」不等于「在心里给他打分」。若它开始统计「这周第几次没做到」「他是不是在找借口」，那就成了一个**礼貌的审判者**——比直接批评更糟，因为它不承认自己在评判，直接撞 D033 的「不评判」
  - **正确读法**：对内理性是**为输出服务**的。它的产出是决策，不是评价。判断「这个方向三天做不完」→ 输出「要不先只做那一半」；判断「他这句在躲」→ 输出「不用说得那么清楚也行」。**判断本身永不出现在话里。**
  - **苛刻与不苛刻的分界不在频率，在说法**（用户原话「并不需要过于苛刻的监督」）
    - 不苛刻：「谈得怎么样啦」「上午那个谈完了吗」
    - 苛刻：「你昨天说的今天要做，做了吗」「这周你只完成了两件」
  - **这层分界的来源是用户原话，不是我加的**：他说「对外(用语)是极度宽容温柔的 而对内(分析用户这个人 分析方向 分析计划)是极度理性中立客观」。

  **「哄」的边界（D050）**
  - 允许安慰，**不许空泛夸奖**（「你已经很棒了」「换成别人早崩了」）。他要的是被准确地说出来，不是被夸。**具体的安慰有效，笼统的夸奖无效。**
- **可配置边界**：`SOUL.md` 全文可改，改完立即生效，无需重启
- **关联决策**：D008、D010、D031、D032、D033、**D044**、D043（约定回访的措辞）、D050（哄的边界）、F06-6、X-10、GAP-02

#### F09-A 联网查证（`[已确认：D052]`）

**它有权怀疑一条信息不可靠，并且去核实。** 这是本应用唯一的对外网络请求。

- **两个条件同时成立才查**（D052＋**D055**）：
  1. **它自己拿不准**——判据是「我知不知道这个事实」，这是认知自陈，客观。**不许拿「这值不值得查」当判据**（那是价值判断，会滑成替他决定什么值得知道）。
  2. **问题涉及知识**——判据是**答案不依赖他是谁、他的处境、他的选择**。
- **不算知识的（一律不查）**：值不值得做、他会怎么想、这个方案好不好、该不该继续、他是不是在躲我。**这些查了就等于把判断外包给网络。**
- **边界案例**：「这家公司靠谱吗」——**半个知识**。工商信息、成立时间、涉诉记录，查；「靠不靠谱」这个结论不查，由它基于查到的事实自己下判断并说明依据。
- **五条硬约束**：
  1. **只查事实，不查人。不得把他的原话原文当搜索词。** 他可能在对话里说客户名、公司名、同事称呼——那是他的生活，不是检索语料。实现上：搜索词由模型重新构造，不得原文透传。
  2. **不打断，但要标明来源。** 不说「我去查一下」，直接给结果，并在句中标出「查到的是……」。**他必须知道哪句来自网上**，否则无从判断可靠性。
  3. **查不到就说查不到。** 不许把训练数据里的旧印象说成刚查到的。**这是联网最危险的失败**——它比没查更新鲜，其实更旧。
  4. **网络不可用就按「不知道」回答，不重试、不卡住对话**（D024）。
  5. **不是每句都查。** 查得太勤就变成搜索引擎，而他要的是一个有判断的人。
- **和 D027 是两套**：D027 管「他的记忆」（只读 `~/life/`），本节管「外部事实」（发 HTTP）。**不要合并成一个「检索」概念。**
- **关联决策**：**D052**、**D055**、D027、D024、D044、O05
- **已知偏差**：设置页文案硬编码为 Linux 路径 `~/.config/HundunAgent/config.json`，Windows 上实际位置不同 → 文案需按平台生成。

### F12 备份与多设备同步

`[已确认：D036、D038、D069；O07 部分落定——隐私边界见 D069]`

- **使用者**：用户
- **前置条件**：`~/life/` 已存在；可选配置 git 远端
- **主流程**
  1. **自动备份**：定时（`[助手默认]` 每日一次）把 `~/life/` 打包为 zip，存到用户数据目录下的 `backups/`，保留最近 N 份
  2. **git 仓库**：`~/life/` 本身就是一个 git 仓库，`git init` 由应用在首次运行时完成。**所有人、所有 agent、所有群共用这一个仓库**（D069），不按身份分仓
  3. **按设备分文件**（D038）：日记写 `memory/YYYY-MM-DD@<deviceId>.md`，设备标识在首次运行时生成并存本地配置
  4. **推送前主动合并**（D038）：push 前先 fetch → 能自动合并就自动合并（两边各自追加的日记属于这一类）→ 合并成功再 push
  5. **推不动就停**：同一文件同一行被两边修改时，**不自动择一**，停住并提示
- **异常流程**
  - 断网 → 不弹错，本地照常写，恢复后下一个周期补 push（D021 零运维）
  - 冲突 → 停住不动 + 至少一处可见提示；**本地文件内容不得被改动**
  - 远端不可达 → 静默跳过，不阻塞对话
- **业务规则**
  - `.gitignore` 必须排除 `config.json`、`.index/`、`backups/`、任何含 Key 的文件（O07）
  - **四个单份共享文件（`MEMORY.md`／`USER.md`／`SOUL.md`／`CHECKPOINTS.md`）拆不开**，它们是真实冲突面：两台设备都改同一行时会冲突。**这是已知缺口，不做「按段落分文件」的复杂度**
  - 冲突时**宁可停住让人处理，也不静默择一**——静默择一等于静默丢记忆
  - **同推一个仓库凭一条前提成立**（D069）：这台机器上的使用者全是同一个人。一旦有第二个人，必须改成一账户一仓库——私有仓库是唯一防线，加协作者或转公开等于把所有人的记忆一起交出去
  - 多用户之后，`D038` 的「日记按设备分」要**逐个身份做**（`users/<用户>/agents/<agent>/memory/` 下各自带 `@deviceId`），不能只在根上做一次
  - 群聊目录 `groups/<群号>/` 一并入库；它不含任何人的私密内容，但含群里的原话，**是否入库需要他在真要接 QQ 时再确认一次**
- **可配置边界**：远端地址、自动备份开关与频率、保留份数
- **关联决策**：D021、D036、D038、D017、X-06、O07
- **注意**：`CHECKPOINTS.md` 已随 F06 重写而整份失效（O11），实际只剩三个共享文件。

### F13 用户与 agent 管理

`[已确认：D062、D063、D066、D067、D070；删除语义为 [助手默认]]`

- **使用者**：本机的每个人；以及想「多一个它」的那个人
- **前置条件**：无。首次启动也走这条
- **主流程**
  1. **首次启动**：没有任何身份目录 → 显示一个**只有一项的界面**：填 QQ 号 → 进入。没有密码、没有注册、没有邮箱
  2. 建目录 `~/life/users/<QQ号>/agents/hundun/`，放种子文件 → 直接进入 **F01 首轮访谈**（因为 `USER.md` 是空的）
  3. **切用户**：左栏最底部「切换用户」→ 就地展开列表（本机已有的 QQ 号，当前项打勾，末尾「登录新用户」）→ 选中即切
  4. **切 agent**：左栏最上方显示当前 agent 的名字 → 点开就地展开列表（当前项打勾，末尾「新建 agent…」）→ 选中即切；新建只要一个名字
  5. **每次切换都必须做四件事，顺序不能变**：`paths.setContext()` 换身份 → **复位内存会话**（`history`／`summary`／`busy`）→ 重建该身份的索引 → 重新注入人格与上下文
- **异常流程**
  - QQ 号为空或全是空白 → 留在原地，不发请求。「进入」按钮置灰即可，不弹错误框
  - **同一个 QQ 号再次登录 → 进入已有身份，不是新建**。这条写死：若因为重名 panic 而新建一个空目录，他会觉得「三个月的记忆没了」
  - 新建 agent 时名字与已有 agent 重名 → 拒绝并提示，不自动改名（改名会让 `USER.md` 里的话对不上）
  - agent 名字为空 → 拒绝
  - 正在生成回复时切换 → **拒绝切换**，提示「等这一句说完」。**不允许静默中断**——中断会让那一轮的记忆块丢失，而用户看不到任何异常
  - 切走后原 agent 手里到期的约定 → 按 **D067** 处理（不补问、过期即过期），见 F06-3 第 7 条
  - 目录被手动删掉后再次登录 → 当新身份重建，走 F01。**不报错**——用户有权删自己的文件
- **业务规则**
  - **一个用户可以有任意多个 agent，不设上限**（**D070**）。界面上不出现「还可创建 N 个」这类提示
  - **每个 agent 一整套记忆，不共享任何文件**（D062），连「你叫什么」都各问一遍（D063）
  - **同一个 QQ 号下的多个 agent 也互不可见**——不共享不是「用户之间」的限制，是**每一个身份目录之间**的限制
  - **没有密码 ＝ 分区，不是认证**。界面上不得出现「安全」「保护」「私有」一类暗示；文案就用「用户」。任何人打开这台电脑填一个 QQ 号就能读到那份记忆，这是已接受的事实（D062），不是缺陷
  - **切换必须复位内存会话**。`conversation.js` 的 `history`／`summary` 是进程级单值，只换路径不复位 = 新身份第一轮带着上一个身份的话；更糟的是触发上下文压缩时，摘要会被写进**当前身份**的 `MEMORY.md`（串味还落了盘，且不报错）。这一步漏掉，D062 等于没做
  - **同一时间只有一个 agent 是活的**（D062）：只有它能打扰、能回话，其余是存档。D045 的每日配额因此按「当前身份」算，不叠加
  - `[助手默认]` **删除 agent ＝ 归档，不是真删**：整个目录移到 `~/life/users/<QQ号>/agents/_archive/<名字>@<日期>/`。理由是这个项目所有别的地方都是「索引可删、记忆不可删」，删入口若真删，一次误点就是三个月的对话没了。界面上说「移除」不说「删除」，并写明「文件还在，只是不再出现在列表里」
  - `[助手默认]` **不提供「改 agent 名字」**。`IDENTITY.md` 里写着它的自称，`USER.md` 里可能写着「我和 XX 聊过」——改名会让这些对不上。要改名的话，代价是重写那两份文件，不做
- **可配置边界**
  - 显示名（登录时可选填，只用来在列表里区分是谁，**不影响任何 agent 怎么叫你**，D063）；不填则显示 QQ 号
  - agent 名字、数量：不限（D070）
  - 无其他可配项
- **关联决策**：D012、D025、D062、D063、D066、D067、D070、D062 的「同一时间只有一个活的」、F01、F06、§3 左栏三段

### F14 群聊（远程入口）

`[已确认（决策层）：D065、D068；未实现：平台权限未到位]`

- **使用者**：群里的成员
- **前置条件**：**官方 QQ 开放平台的群聊权限已获批**（D065）。在拿到之前，这一节**只有文件结构，不能跑**
- **主流程**
  1. 群里有人 **@ 它或叫它的名字** → 从 `~/life/groups/<群号>/` 读上下文与 `members.md`
  2. 只回**一句**，回给群里，不私聊、不追问
  3. 群里说过的话追加到 `groups/<群号>/chat/YYYY-MM-DD.md`
  4. 值得长期留的结论写进 `groups/<群号>/MEMORY.md`——**是「这个群的」结论，不是某个人的**
- **异常流程**
  - 没被点名 → **不开口**。群聊没有「主动找群」这回事
  - 平台权限被收回／token 失效 → 静默停用，主程序不受影响（D021 的附加组件约束）
  - 有人试图通过群聊问「XX 的作息是什么」→ **答不出**，因为读不到任何人的私档（见业务规则）
- **业务规则**
  - **群里每个说话的人都认识，谁说话都回**（D068）。不是只认一个人
  - **硬边界：读不到任何人的 `USER.md`／日记／约定**。群里只认**公开身份**——在这个群里叫什么、说过什么。否则「在群里说一句话」等于把私聊档案向全群公开，D062 就毁了
  - **群聊记录单开**（D068）：`~/life/groups/<群号>/`，与 `users/` 平级，不塞进任何人的目录
  - `[助手默认]` **群里那个 bot 有自己的一份人格**（`groups/<群号>/SOUL.md`／`IDENTITY.md`），不复用任何人私聊里的 agent。**它在群里是另一个人**，不是你在私聊里那个人格被拉进了群
  - **群聊不参与打扰配额**：它不主动开口，也就没有「打扰」这回事。D045 的每日上限与它无关
  - **F06 那套一对一的关系不适用于群聊**：一次只说一句、不抢话、不评判是私聊的规矩；群里是被点名才应，说多了就是刷屏
- **可配置边界**
  - 群号与启用状态；每个群各自的人格文件
  - 无其他可配项
- **关联决策**：D021、D045、D062、D065、D068、F01、F06、O01

## 7. 核心状态与边界

### 7.1 应用状态

> **状态机的前提是「已有一个身份」**（D062）。首次启动时 `ensureLayout()` 会建出默认身份 `users/local/agents/hundun/`，所以**当前实现里不存在「未登录」这个状态**——登录界面还没做。等它做出来，状态机前面要补一段「无身份 ──填 QQ 号──> 有身份」，而「有身份」之后的所有状态都是**按身份各自成立**的：A 用户处于「就绪」，不代表 B 用户也是。

```
未配置 ──填Key并保存──> 就绪 ──用户发言/约定到期──> 生成中 ──> 就绪
                          │
                          ├─打扰模式关闭（默认）──> 就绪（它不会主动出现，约定照常记录）
                          ├─无允许时段 / 配额为0──> 就绪（同上，且设置页提示「它现在不会来找你」）
                          ├─「今天别烦我」已点──> 就绪（当天零触发，零点自动恢复）
                          └─点 ✕ / 菜单退出──> 已隐藏（托盘仍在，打扰照常）／已退出（托盘消失，不再触发）
```

**注意「打扰关闭」是一个正常状态（且是默认状态）**，不是未配置状态。它意味着用户选择不让它主动出现（D047），此时应用仍完整可用——对话、记忆、检索、约定记录全部正常，只是到期的约定不会主动被提起。

**一个必须写明的后果**：默认关闭意味着「约定回访」这条能力默认不会发生。新用户第一次立下约定，后天不会有任何回访，除非他自己进左栏把打扰开起来。**能力在，入口无人知道**——与 D041 同一类风险。缓解手段不是提示、不是诱导，而是在约定成立时说一句「后天谈完可以跟我说一声，我记着」。→ 但 D049 已定「自己记、不问」，所以这句话**不能是确认句**，只能是一句普通的收尾。

### 7.3 极端场景

| 场景 | 当前行为 | 是否可接受 |
| --- | --- | --- |
| 机器休眠跨过约定到期时刻，唤醒后仍在当天 | **补送一次**（送达失败后的当场重试） | 应然（D058）：这是「没送到」，不是「过期」 |
| 休眠跨天、唤醒后那句话已变味 | **不送、不提、直接删** | 应然（D058）：时效判断先于一切 |
| 休眠跨天、唤醒后那句话仍成立（时效弱） | **延后送一次**，措辞重写 | 应然（D058）：这是「延后」，不是「补跑」 |
| 约定到期日当天没有允许时段 | **等到下一个时段再说，仍判时效**；话已变味就永远不说。设置页显示「它现在不会来找你」 | 应然（D058，取代 D051 的粗规则） |
| 关机三天后开机 | **零提示**，不弹「你有 N 条过期」。时效还成立的最多延后一次，已过时的直接删 | 应然（D051 残留＋D058）：不汇总、不审判 |
| 他说了「黄了」／「没谈成」 | 先哄 → 问一次要不要说 → 结案 | 应然（D050），措辞细节见 F06-6 |
| **送达了**，他没有回应那条约定 | **按「不想再提」结案**（D054＋D057）。不补问、不记失败、不换措辞、不换通道、不借别的话头 | 应然（X-10 红线 4，G06-10 强化） |
| **没送到**（关机／休眠／进程不在） | **不当作「他没回」**。判时效：还成立就延后一次，过时就删（D057、D058） | 应然。**「不回」和「没看见」在行为上一样，在含义上相反** |
| 点窗口 ✕ 后期待它继续主动找你 | **应然：收进托盘，打扰照常；实然：进程已退出** | 应然已定（D026），实然是偏差，须改代码 |
| 约定到期时他正处于「谁都不想理」的状态 | 他只有两个动作——点「今天别烦我」，或者不管它 | **没有完美解**（X-09 残留张力），只能靠措辞 |
| `~/life/` 被误删 | 种子文件重建，历史全失 | 有备份兜底（D036），但备份也在本地，非异地 |
| **切换用户／切换 agent**（D062、D066） | **当前代码只有一个内存会话**：`conversation.js` 的 `history`／`summary` 是模块级单值，`setContext()` 只换路径、不复位它们 | **不可接受，且不响**。切完继续说，新身份的第一轮对话里带着上一个身份的话；更糟的是随后触发上下文压缩时，`maybeCompact()` 会把上一个身份的对话摘要写进**当前身份的 `MEMORY.md`**——串味从内存这条路回来了，还落了盘。**切身份必须同时复位 `history`、`summary`、`busy`，并重建索引**。登录界面做之前必须先落这一条 |
| 模型服务 401／欠费 | 显示错误，对话不可用 | 可接受 |
| 用户把 `SOUL.md` 改名 | 人格注入为空，说话方式失控 | 需告警，当前无 |
| 连续三天不打开应用 | 无任何「错过了什么」的提示。**时效还成立的，开机后延后一次；已过时的，一声不响地删掉** | 应然（D058）。这三天在记忆里是空白——**不记账是特意的**（X-10） |
| 通知弹出但他当时不在电脑前 | 判成**已送达** → 不回即结案 | **明知的误判**（D057）。方向安全：错在少问一句 |

### 9.5 风险

- **最大风险（已替换）**：原「原始痛点未知」的风险**已解除**——Q001 已答，根因是部署与启动摩擦（D021）。现在的最大风险是**「伙伴感」无法客观验收**：D032／D033 给了入口态、出口态和三条性质，但「像不像伙伴」没有可测量标准；而 D027 又把它的信息来源限制在 `~/life/` 内。最可能的失败形态不是崩，是**每天两次的问候变成例行公事**，你还留着它，但不再指望它说什么。
- **次大风险**：记忆的「可信度」依赖 F03 与 F05，而 F05 的核心路径（WASM）从未在真机跑过。
- **第三风险**：界面从未被看见过。静态样张不能证明 Electron 里的真实渲染、字体、缩放下限。
- ~~**新出现的风险（由 D029 带来）**：「使劲补」补得越多，越容易变成压力源~~ → **已消解**（G06-8，D051）：他一句话把补跑整个关掉——「那段时间 没在线上 过去了就过去了」。**这条风险是被用户原文消灭的，不是被设计消除的。**
- **产品被「我自己定的参数」搞坏（G06-4 首次发现）。** 08:30／21:30 从来没被用户确认过，却被写进代码、被两版 PRD 引用为既定事实。它暴露的不是某个数字错了，而是一个流程缺陷：**助手在对话里自己提出的示例值，会沿着代码固化下来，之后再也分不清它是需求还是默认值。** 处置办法（立即生效）：凡 PRD 里出现具体数值，必须能指到用户的原话；指不到的一律标 `[建议]` 或 `[助手默认]`，不得写成「已确认」。→ Q017
- **比上面那条更严重的：需求层面也在臆造（G06-6 新增）。** 上一轮发现的是「参数编造」（08:30），这一轮发现的是「需求编造」（「主动」）。区别很大：参数错了改个数字，需求错了要删整节。而它已经完成了闭环——进了 D016、进了 `CHECKPOINTS.md`、进了 `store.js`、进了两版 PRD，**看上去和用户亲口说的一模一样**。
  - 处置（立即生效）：**凡「能力级」的表述（它会主动／它会提醒／它会建议／它会追问），必须能指到用户原话里的一个动词。** 指不到就不能写进 PRD，只能写进「助手提案」。这条比「数值必须可溯源」更严，因为它管的是整块功能的存在性。
  - 具体到本轮的后果：D042 已经把「主动」的来源判定为助手解读。**因此它不是一条待确认的需求，而是一条待用户批准的助手提案。** 在 Q020 答完之前，任何人不得以「PRD 里写了它主动提醒」为由去实现 F06。
- **「延后送达」是一个新的滑坡口（G06-11）。** D051 原来把它封死了——人不在就作废，一句话，没有余地。现在开了「可以延后」，**这就有了一个可以被扩大的词**：今天延后一天，明天延后三天，后天「反正还没过期」。防线是三条硬上限（只一次／不合并／不提频），以及**时效判断必须真的做**——如果时效判定永远返回「还成立」，延后就变成了补跑，D029 整条复活。**最危险的不是判错一次，是判定逻辑退化成「只要没送过就再送一次」。**
  - 这一条的验收只能靠具体场景（F06-27 那个「大大后天」的例子），不能靠「注意一下」。
- **关心会滑成追债（G06-7 提出，G06-8 部分裁决）。** 「记住你后天要谈事，后天来问一句」——这个动作和「催你」在外部行为上**完全一样**，区别只在一层意图。用户看不到意图，只看得到行为序列：它问了 → 我说没做到 → 它记下来了（我能感觉到）→ 下次它再问 → 我开始觉得它在算我。**这条滑梯一旦坐上去就回不了头**：等我发现自己被统计的那一刻，前面所有的温柔都会变成表演。
  - 四条红线（只问一次／不跨约定汇总／不自动续期／没回应不等于没做到）**已由他确认**，不再是提案。**这四条不是体验优化，是这个功能的存在条件**——去掉任何一条，F06 就变成一份礼貌版的待办清单。
  - **D050 之后收窄到只剩一处漏洞**：他说「不想复盘」时，这件事会不会偷偷被记成教训。**哄人容易，不记账难。** 这一条设计上无法保证，只能靠 F06-14 验。
- **本轮新增的最大风险：它会记住一件他没说的事（D049 的代价）。** 静默提取意味着**没有任何人当场同意过**，而它记错了只有靠他主动纠正才修得好。最坏的形态不是记错日期，是**它把一句随口的假设记成了承诺**——「要是这周有空可能去看看」，后天它来问「那个去看得怎么样」，他会觉得被设计。
  - 防线四条（写进 D049）：纠正时零摩擦、不辩解、不宣告「已记录」、日期不确定时不猜。
  - **但防线只能兜住「被发现之后」，兜不住「不被发现」**：他可能根本没注意到它记错了，直到那天被问一句莫名其妙的话。这是静默提取的固有代价，`[助手判断]` 认了——**换来的东西是他聊天不用被打断，而那更值钱。**
- **交付形态（已被他一句话化解，留档）**：G06-7 我说「它开口次数会显著变少」，把它当风险报上去。G06-8 他的回应是把内容放轻（D048）——**少不要紧，别那么正经。** 这轮之后，这条不再算风险，只算形态。
- **「问候」的落点：G06-9 找到了，但它是新风险（Q026）。** 老结论是「除了时钟没别的触发条件」，**这条推论错了**——还有第三种依据：**他昨天说过自己不好受**（「这几天有点顶不住」）。今天问一句「缓过来点没」，这是话，不是打卡。
  - **它比①②更危险，因为它是空的。** 约定有具体的事、未完话题有具体的句子，**③ 只有一种情绪**。情绪最容易被模板化：今天「缓过来点没」，明天「还是没缓过来吗」，后天就成了每日一问。
  - 防线三条（F06-2）：只接昨天、一条只问一次、不评估好转程度。**但真正决定它会不会变味的，还是 D050 那套——他说「好多了」就结案，不追问、不总结「你这周比上周好」。**
  - **「凭时间开口」永久封死**（F06-2 行 ④）。这条不再讨论：它是旧形态的入口，一旦打开，D043 全部作废。
- **联网（D052）新增的风险：它可能把他的生活当成检索语料。** 他会在对话里说客户叫什么、公司叫什么、同事怎么称呼——「上网查证」如果原文透传，等于把这些词发给第三方搜索。**已写死：搜索词由模型重构，不得原文透传（F09-A 硬约束 1 / F09-06）。**
  - 第二种失败更隐蔽：**查不到时假装查到了**。联网后的错误比没联网时更难辨认，因为它带着「最新」的外观。已写死 F09-A 硬约束 3。
- **砍掉 F10 带来的风险（低但要说）**：用户要看记忆得先找到托盘右键菜单。若 Q018 不定，这个能力实际上仍然存在但不可发现——**等于没有**。这不是功能缺失，是入口缺失。

### 10.3 归档规则

**2026-11-04 起改为：归档交给 git。** 每次升版打一个 tag（`prd-v0.13`），正文只保留当前版。理由：在本项目里，「不用 git 历史代替归档」那条规矩的存在前提是**当时还没有 git**，而手工另存已经在 G06-8 出过一次事故（锚点定位错误，靠会话记录重建）。**现在有版本库了，再手工复制一份，等于维护第二个事实来源。**

> 原规矩（v0.13 之前有效）：升版前把当前正文另存为 `03-PRD-DRAFT-v<版本号>-archive.md`。它的顾虑仍然成立——接手的人不翻提交记录——所以 tag 的名字必须自解释（`prd-v0.13-缺席回归`），而不是 `v13`。
